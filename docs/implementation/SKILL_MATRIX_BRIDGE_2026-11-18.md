# Skill 矩阵恢复推进：研究卡到写稿第一批

## 基线与范围

用户要求整体前期策划矩阵与版式审美同步推进。当前运行矩阵为十一章、75节、98项（原97项加V14），不是旧八大项62模块。旧62模块、矩阵登记与Web阶段稿是不同链路，不能合计为“全部可用”。

本批先打通 A04 → C组研究卡 → W01/W02/W03，而不是再建独立入口或另一套任务系统。沿用现有确认目录、总档冻结、队列、模型策略、版本事务和工作台。研究与写稿可合并一次调用，计划与候选结论分别记录。矩阵大多数专业能力尚未独立业务验收。

## 实施

1. 从已确认任务编译稳定ID计划，保留用户汇报顺序，提供独立研究顺序与03章反馈边界。未选择章不加入；缺A03时只允许资料梳理语义，不推定完整研究条件。
2. 新工作台整稿请求 `researchMatrix:true`。服务器编译/冻结计划与Skill哈希。客户端不能提交伪造计划。旧无标记API、旧存量稿保持兼容。
3. 模型返回每项任务的研究卡，区分事实、推断、拟议建议，保留真实内容引用、假设、缺口、实际选用C子能力。结构与引用不符拒绝保存，不用已有正文冒充研究完成。
4. 同一稿保存研究卡和对应正文，多个展示节可指向同一原研究任务。工作台“内部备注”展示对应研究卡及原件出处，明确尚未独立业务验收。
5. 局部改写保留研究卡并标记研究未重跑，不增加模型调用；新资料仍走原有失效门禁。全稿采用不改研究验收状态。

## 不在本批的能力

并未建立每个 C Skill 的独立执行器、GIS/成本计算/外部竞品调查工具，也未证明模型业务质量。执行顺序是同次调用的研究指导，不是多Agent调度。未新增外部服务或扩大资料外传范围。旧专业模块门禁不变。

后续主线应分别验收：02区域尺度/来源、03-04-05假说与反馈、07-10产品/空间/运营/投资数值一致性、A05资料变化影响与复核。当前研究卡为其提供可追溯产物接缝，不代表上述成果已合格。

定向纯测试通过；新增真实API/数据库测试进入完整CI。云容器连接 PostgreSQL socket 返回 EPERM，不能把这项记为成功。未调用真实供应商模型，未替用户修改生产资料、创建或发布稿件。统一合并部署由原部署负责人执行，部署前必须完整CI和对应回归通过。
