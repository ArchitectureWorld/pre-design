# 详细汇报大纲编制

标准项目导出采用 `compileReportOutline`，不再将全部成果固定压成十页。旧的 Contract-neutral 摘要投影器保留兼容，标准目录输出不再用其内容作为最终草案。

## 编制规则

- 章节 → 专题 → 页级表达；按完整论点、相邻内容关联和图文容量组织页面，不将每个成果字段机械拆成单页。
- 按背景、条件、问题、机会、定位、比选、功能、空间、投资实施组织成果；同一专题可引用多个成果，一个复杂成果可展开多页。
- 项目的 `DG06.topics` 转为有名称的关键议题页；跨成果页对照建设必要性、推荐依据、功能规模、空间可行性及投资实施条件。
- 详细内容来自冻结成果的完整专业字段，不受旧 `facts` 八条限制。正文按容量选取完整表达、去除重复并回并短尾页，不设置项目总页数；完整专业明细保留在依据表中供追溯，不删除源成果。
- `text` 保留完整信息，`contentText` 去除重复的来源元信息，`basis/fieldPath/evidenceRefs` 保留依据与证据身份；纯资料元信息进入来源说明，不单独凑正文页。
- 不修改源数据、不调用模型重跑 57 项。缺失依据、审批条件与测算假设不升级成已证实事实。投资基线和财务模型不一致时，提示核对而非替用户改数。
- 页面正文不含“本页回答”“编写主线”等内部编写指令；讲解稿独立为可口述的对外台词，解释本页论点与成立条件，不新增内部说明栏目，也不进入排版正文。
- 素材先进入项目素材库，再根据本页证据与明确绑定进入当页素材库；细节页不继承同成果其他细节的素材，不按整章铺图。原件登记、素材角色及缺失提示见 [素材登记](presentation-material-registry.md)。

这是可编辑的详细汇报草案，不等同于已完成配图、排版或独立事实核验的正式汇报文件。缺少可读取图像或视频时如实提示，不能将占位文字或附件通道支持视为视觉内容已完成。

## 兼容与更新

保留原十页的 page、draft、叶节点与主内容块标识，新增专题和细页使用稳定语义键。合页会调整部分细节页标识；旧批注与审阅历史不删除、不伪改目标。相同成果版本可重新同步，无须伪增 Pre Revision。继续使用现有标准项目事务写入、外部修改冲突保护与布局所有权边界；不自动使用 `--force`，不重建已有人工排版。
