# Pre-design 2.0.0 产品与插件架构

## 1. 唯一产品身份

本仓库当前产品、插件代码和 npm 包候选版本统一为：

```text
Pre-design 2.0.0
@architectureworld/dsh-preplanning-agent@2.0.0
```

当前支线：

```text
architecture/pre-v2.0.0
feat/pre-v2.0.0
```

`2.0.0` 是 Pre 自身版本，不表示任何外部工具或 Contract 的版本。当前尚未创建 `v2.0.0` Tag 或 Release。

## 2. 系统架构

```text
DSH Harness
├─ 管理 Agent、模型、Session、Tool 调用和执行循环
│
├─ Pre-design 2.0.0
│  ├─ 前期策划 Skill
│  ├─ 8 章、57 项专业工作流
│  ├─ Tools / Commands
│  ├─ Project State / Evidence / Assumption / Question
│  ├─ Gate / Proposal / Pre Revision
│  ├─ 原始资料与正式素材处理
│  ├─ 报告内容生成
│  └─ 标准项目目录创建、填写、验证和交付
│
└─ 其他独立插件和工具
```

Pre-design 是可执行 DSH 插件。Skill 是插件内部的专业能力，不等于整个插件；DSH Harness 才是 Agent Runtime。

## 3. Pre 内部职责

Pre 2.0.0 负责：

- 创建和维护前期策划项目；
- 推进专业工作流并冻结可追溯成果；
- 保存 Pre 自身的 Session、Gate、Proposal、Revision 和恢复记录；
- 导入项目原始资料；
- 生成、加工和采用正式汇报素材；
- 将专业成果转换为结构化大纲、页面草案和讲解稿；
- 调用已锁定的外部 Contract 生成稳定 ID；
- 在 staging 中写入完整成果并运行外部 Validator；
- 仅在验证通过后原子发布标准项目目录；
- 继续保留既有 HTML、PPTX 和 PDF 输出能力。

## 4. 外部 Contract 是依赖，不是产品主线

Pre 2.0.0 当前消费：

```text
Presentation Standard Project Directory 0.1.0
@architectureworld/presentation-contracts@0.1.0
```

固定坐标：

```text
Authority: ArchitectureWorld/presentation-tools
Commit: 974668d308728386ea005c9e77d58ebff9372f0a
Schema Set SHA-256: 5bd329fcc8503ff7a48b3430e41b38dd264ae486cee7372a39cbbcccc2de2ebc
Lock: docs/contracts/presentation-standard-project-v0.1.0-lock.json
```

该 Contract 只定义可交换项目格式。`presentation-tools` 的产品版本可以独立升级到 `0.1.1`、`0.2.0` 或其他版本；除非 Contract 坐标发生变化且 Pre 主动完成适配，Pre 2.0.0 不随之升版。

## 5. 解耦边界

```text
Pre 内部专业状态
        ↓ Adapter
标准项目目录
        ↑ 其他工具读取或修改
```

标准目录只承载：

- 项目基本信息；
- 汇报规则；
- 大纲；
- 页面清单；
- 逐页草案；
- 讲解稿；
- 原始资料清单；
- 正式素材清单；
- 来源追溯。

以下对象只属于 Pre 内部，不得进入标准目录：

- Agent Runtime；
- DSH Session；
- Gate；
- Proposal；
- Review 执行状态；
- ProjectHead；
- Revision/CAS；
- 自动同步状态；
- 冲突状态；
- 调用方恢复记录。

## 6. 项目与身份

Pre 项目身份与标准项目身份相互独立：

```text
preDesignProjectId      Pre 内部专业项目身份
presentationProjectId   外部 Contract 定义的标准项目身份
```

二者通过 Pre 内部 Binding 持久化映射。所有标准对象 ID 均通过外部 Contract `createStableId()` 首次创建，并按稳定业务键复用；标题、数组下标、页码和文件名不能作为身份。

## 7. 写盘和验证

```text
创建 sibling staging
→ Contract Factory 生成最小目录计划
→ 写入 Canonical JSON
→ 复制 source-materials
→ 写入正式 assets
→ 计算 MIME、sizeBytes、SHA-256
→ 更新 Manifest
→ Contract 全量验证
→ 验证通过后原子发布
```

失败时不覆盖旧成果、不登记成功、不保留可见半成品，并返回结构化诊断。

## 8. 当前实施状态

- Pre 2.0.0 标准项目输出代码已完成；
- 外部 Contract `0.1.0` 已精确锁定；
- 专项测试、TypeScript、完整构建、全仓测试和构建产物测试已通过；

- 真实 DSH 独立 Profile 烟测尚未完成；
- 尚未合并主线或发布 `v2.0.0`。

## 9. 发布门禁

发布 Pre 2.0.0 前必须完成：

1. `feat/pre-v2.0.0` 最终 HEAD 全部 CI 通过；
2. `architecture/pre-v2.0.0` 与开发支线基线一致；
3. 独立 DSH 测试 Profile 安装与启动通过；
4. 核心命令和标准目录导出完成真实烟测；
5. Handoff、版本矩阵和安装说明一致；
6. 获得合并、Tag 和 Release 授权。
