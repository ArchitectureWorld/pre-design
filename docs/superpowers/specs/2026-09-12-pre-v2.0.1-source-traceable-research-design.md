# Pre 2.0.1 可查数据源与分析链设计

日期：2026-09-12
目标分支：`feat/pre-v2.0.1`
基线：`feat/pre-v2.0.0` 保持现有可部署执行路径，不在该分支继续写入本功能生产代码。

## 1. 目标

把现有 57 项专业工作流升级为一条可查、可复核、可重算的数据链：

```text
项目正式资料 / 官方网站 / 官方开放数据 / 权威行业数据 / 专业计算
→ 采集
→ EvidenceRecord
→ 标准化 / 交叉核验
→ 确定性汇总与计算
→ AnalysisTrace
→ LLM 专业解释与综合
→ 独立 Evidence Validator
→ Project State
→ Report / Presentation
```

每个关键事实、指标和结论都必须回答：来源是什么、何时取得、原始位置在哪里、原始值是什么、如何清洗/汇总/计算、采用什么方法、最终结论依赖哪些证据、当前置信度和限制是什么。

## 2. 版本隔离

## 3. 数据来源优先级

```text
P0 项目正式资料 / 实测数据
P1 政府、法定机构官方数据
P2 官方标准、政府认可专业公共数据
P3 权威行业数据库、专业机构公开数据
P4 地图 / POI / 市场平台等辅助数据
P5 LLM inference / assumption
```

P5 永远不能单独形成 `fact`。高风险事实至少需要 1 条 A 级证据；普通事实至少需要 1 条 A/B 级证据，或 2 条独立 B/C 级来源交叉验证。

## 4. 核心对象

### DataSourceCatalog

登记允许使用的数据来源：`sourceId / name / publisher / priority / authorityLevel / homepage / allowedDomains / accessModes / supportedDataKinds / freshnessPolicy / reliabilityGrade / notes`。

### WorkflowResearchSpec

每个 Workflow 对应一份可执行研究计划：`workflowId / requiredDataPoints / optionalDataPoints / preferredSources / queryTemplates / extractionRules / normalizationRules / aggregationMethod / analysisMethod / crossCheckRules / freshnessRules / minimumEvidence / fallbackPolicy / outputClaims`。

### EvidenceRecord

真实采集记录：`evidenceId / sourceId / sourceType / sourceUri / sourceTitle / publisher / publishedAt / capturedAt / asOf / locator / rawValue / normalizedValue / unit / contentHash / reliability / claimClass`。

### AnalysisTrace

结论分析链：`traceId / workflowId / claimId / inputEvidenceIds / inputObjectIds / methodId / methodVersion / parameters / calculationSteps / outputValue / confidence / limitations`。

## 5. 第一批真实来源

Phase A/B 首批只接入公开、可验证、无需绕过登录/验证码的来源：

- 当前 DSH Workspace 中项目正式资料；
- 国家统计局：`stats.gov.cn`；
- 中国政府网政策库：`gov.cn`；
- 住房城乡建设部：`mohurd.gov.cn`；
- 自然资源部：`mnr.gov.cn`；
- 全国标准信息公共服务平台：`std.samr.gov.cn`（旧 `openstd.samr.gov.cn` 仅作为兼容入口）；
- 中国气象数据网/国家气象信息中心：`data.cma.cn`；
- 国家企业信用信息公示系统：`gsxt.gov.cn`。

地方数据采用“项目所在地官方机构域名发现 + 白名单确认”的方式扩展，不能默认信任搜索结果中的第三方转载站。

## 6. 分析规则

- 事实型：采集 → 单位/时间/空间口径标准化 → 去重 → 交叉核验 → 指标。
- 对比型：统一指标口径与统计期 → 对比矩阵 → 差异 → 专业判断。
- 空间型：可信边界 + GIS/POI → 几何计算 → 距离/覆盖/密度 → 结论。
- 规模型：目标人群/需求 → 标准/基准 → 参数 → 公式 → 区间/敏感性 → 建议规模。
- 投资型：工程量 → 单价来源 → 基准日 → 税费/预备费 → 汇总 → CAPEX / 生命周期成本。

确定性计算不得由 LLM 心算产生。LLM 只负责解释、比较、综合和提出待验证假设。

## 7. Workflow 执行链

```text
Workflow READY
→ WorkflowResearchSpec
→ Research Task
→ Workspace / Web / API / Professional Tool Provider
→ EvidenceRecord
→ Evidence Validator
→ Deterministic Aggregation / Calculation
→ AnalysisTrace
→ LLM State Candidate
→ Quality + Evidence Gate
→ auto_pass / auto_revise / blocked_external / needs_human
→ Project State
```

## 8. 自动化与人工边界

目标继续保持全自动为主。人工只进入：高等级来源冲突、法定边界/投资等高风险事项、关键外部资料无法取得、自动修订达到上限、用户主动修改或锁定结果。

## 9. 实施阶段

### Phase A — Research Contract Foundation

建立 DataSourceCatalog、WorkflowResearchSpec、EvidenceRecord、AnalysisTrace 的类型、JSON Schema、Registry、打包规则和测试；同时完成首批真实官方 Source Catalog 与 3 个代表性 Workflow Research Spec（项目认知、政策法定条件、投资估算）。

### Phase B — Real Providers

实现 Workspace Provider、官方 Web Search/Fetch Provider、公开 API Provider；保留 Provider 接口用于后续 GIS/BIM/造价等专业工具。

### Phase C — Evidence Validator + Deterministic Methods

实现来源等级、域名、时效、冲突、最小证据规则；引入确定性 aggregation/calculation 与 AnalysisTrace。

### Phase D — Runtime Integration

把真实 Evidence/Trace 注入 Workflow Analyzer；`auto_pass` 不再接受纯 Agent 自报，必须由独立 Evidence Validator 通过。

### Phase E — 57 Workflow Coverage

57 项逐项完成“查什么、去哪里查、如何提取、如何汇总、如何计算、如何核验、缺失怎么办、最终形成什么结论”，并用真实项目做端到端回归。

## 10. 验收标准

任取一个关键结论，系统必须可还原：来源网站或项目文件、数据时间、原始定位、原始值、标准化值、计算步骤、方法版本、输入证据、结论、置信度与限制。不能还原完整链路的结论不得进入完全可信的 `auto_pass`。
