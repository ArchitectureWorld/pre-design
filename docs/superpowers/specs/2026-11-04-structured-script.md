# 章、节、条、页与双栏审阅

用户四项要求：正文是正式汇报的结构化内容；备注简明、与正文对半独立滚动；可视化首轮须整稿通过后统一生成，后续可单页或多页修改；一节可有多条、一条对应一页。

## 方案

沿用现有原型及版本化 workflow，只新增条目层。新稿 formatVersion=2：每个 block 仍为已确认节，含 items；每条有短标题、paragraphs、points、evidenceIndexes。新稿每条至少包含一项要点，段落仅作必要引言或论证，不允许退回整段文字配空points。标题/段落/条款用安全结构渲染，不接受任意 HTML。避免“项目登记名称”“本轮做了”等过程口吻；直接写项目名称、区位等有依据内容，缺项放独立备注。条数按内容决定，不机械拆句凑页。

正文和内部备注各50%，各自滚动；备注按范围目标、边界管控、资料适用等主题去重归类，短摘要直接显示，原始限制/依据可展开。保存原始限制，界面不重复粘贴完整问询原文。移动端可切换正文/备注单栏。保留旧稿可读和下载，不重写历史版本。

条 ID 为 outline-章-节-item-序号，修改引用绑定 draftId+blockId+itemId。单条修改仅替换该条，其他条/节保持；修改后的新稿不继承整稿确认。新增明确“确认整稿”，逐条审阅不隐式生成成果。

首次“生成整套成果”仅在当前结构化整稿确认后允许：服务端读取完整稿件，一条一页，统一主题/字号/色板，保存完整页序及源稿版本。当前实现是可预览和下载的 HTML 汇报页，复用结构化文字与安全版式，不伪造图片、地图或统计图。用户没点生成时没有页面节点或占位。生成后可选择单页/多页使用同一主题调整版式（要点/双栏/重点），保存新版本，其他页不变。脚本变化须重新确认并生成对应完整版本，避免混用新旧正文。

真实项目保持 V6、五章顺序、资料原件和 Core revision。此次真实运行生成结构化新稿，禁止代用户整稿确认或生成可视化；全流程视觉门槛与单/多页修改通过隔离浏览器/API/数据库测试。

## 不扩展

不改原模板，不改 Web 4320/DSH 3080，不放开专业研究数据门槛，不新增图像服务或伪造可行性结论，不提交或推送仓库。措辞/推理专项只处理本次明确的正式汇报结构要求。
