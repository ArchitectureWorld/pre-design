# Pre-design 大纲、草案与素材输出冻结基线 V2.0.0

## 0. 冻结结论

`pre-design` 是可执行的 DSH 插件，内置前期策划 Skill，并包含专业工作流、Tools、Commands、状态、资料处理和标准文件生成能力。

本文件只冻结 `pre-design` 如何把前期策划专业成果整理成 Presentation 标准项目内容：

```text
57 项专业成果
→ 汇报大纲
→ 页面清单
→ 逐页草案
→ 独立讲解稿
→ 正式素材引用
```

`pre-design` 不生成排版，不决定字体、字号、颜色、页面坐标、模板、PPT 母版或最终媒介版式。

结构文件的最终字段、Schema 和 ID 格式由 `presentation-tools` 统一定义。

---

## 1. 内容生成输入

投影输入必须来自同一份冻结的 `pre-design` 专业状态，包括：

- Project 和 ProjectBrief；
- 当前有效的专业 State Object；
- 当前有效 Evidence；
- 当前有效 Assumption；
- 当前有效 Decision；
- Gate 结果；
- Question 和缺失信息；
- 已采用专业素材；
- 当前 `pre-design` Revision。

不得读取：

- Presentation DOM；
- React 状态；
- 排版坐标；
- Layout 文件；
- legacy 页面规划结果；
- 未采用候选素材；
- 已过期、被否决或 supersede 的专业内容。

---

## 2. 内容生成总流程

```text
冻结的 pre-design 专业状态
        ↓
有效事实、判断、假设、建议和决策收敛
        ↓
8 类默认主题基础映射
        ↓
内置 Skill 与当前 DSH Agent 在约束下进行项目自适应
        ↓
OutlineDocument
        ↓
单页单核心结论拆分
        ↓
PageManifest + DraftPageDocument[]
        ↓
独立讲解稿 + assetId 引用 + sourceRefs
```

禁止：

- 一个专业对象机械对应一页；
- 把 57 项工作流直接变成甲方汇报目录；
- 为凑页数生成重复内容；
- 用排版需要改变专业结论；
- 将具体案例词写进通用默认骨架。

---

## 3. 默认汇报骨架

第一版采用“8 类稳定默认骨架 + 项目自适应”。

| 顺序 | 内部主题键 | 默认主题 | 主要内容 |
|---:|---|---|---|
| 01 | `project_brief` | 项目认知与任务 | 项目身份、背景、任务目标、对象、边界和基础约束 |
| 02 | `diagnosis` | 现状与核心问题 | 现状基线、需求缺口、核心矛盾、限制条件和问题优先级 |
| 03 | `opportunity` | 发展机会 | 政策、趋势、资源、市场、场景和价值机会 |
| 04 | `positioning` | 项目定位与目标 | 使命、目标体系、价值主张、定位和不可突破边界 |
| 05 | `program_product` | 产品与功能体系 | 功能组合、产品体系、使用人群、服务内容和场景 |
| 06 | `spatial_strategy` | 空间策略 | 总体结构、空间网络、分区、节点、尺度和专业图件 |
| 07 | `delivery_model` | 运营、投资与实施 | 运营、投资、主体、分期、关键路径和风险控制 |
| 08 | `decision_next_steps` | 决策事项与下一步 | 已确认决策、待决事项、授权请求和下一步行动 |

内部主题键只属于 `pre-design` 的投影规则，不要求进入 Presentation 通用核心。

---

## 4. 项目自适应

默认骨架不是固定模板。

允许：

- 省略不适用主题；
- 合并高度关联主题；
- 拆分内容过多且具有独立判断链的主题；
- 增加项目确有必要的专业主题；
- 调整章节顺序；
- 根据受众和汇报目的调整叙事重点。

必须满足：

- 不生成空章节；
- 不遗漏影响决策的重要有效结论；
- 每次调整可追溯到专业对象和证据；
- 不改变底层专业状态；
- 不把具体城市更新、滨水、文化街区等案例内容写成默认值；
- 相同冻结输入应得到确定性或可解释的稳定结果。

---

## 5. 57 项成果映射

采用“确定性基础映射 + 有约束的智能调整”。

### 5.1 基础映射

| 专业成果语义 | 默认主题 |
|---|---|
| 项目身份、启动原因、任务边界、基础条件 | 项目认知与任务 |
| 现状、问题、需求、缺口、矛盾、约束 | 现状与核心问题 |
| 趋势、政策、资源、市场、机会窗口 | 发展机会 |
| 使命、目标、定位、价值主张、非目标 | 项目定位与目标 |
| 功能、产品、对象、活动、使用场景 | 产品与功能体系 |
| 总体结构、网络、分区、节点、尺度、场地分析 | 空间策略 |
| 投资、运营、主体、分期、路径、风险 | 运营、投资与实施 |
| 有效决策、待决事项、授权和下一步 | 决策事项与下一步 |

### 5.2 智能调整约束

内置 Skill 与当前 DSH Agent 可以根据项目实际内容调整，但必须：

- 只使用当前有效专业对象；
- 保留来源对象、专业 Revision 和证据引用；
- 不重新纳入过期、被否决或 supersede 的内容；
- 不为了视觉均衡制造无依据章节；
- 不把修改大纲当作修改专业事实；
- 对重要调整保留可审计原因；
- 不要求 Presentation 理解任何专业对象。

---

## 6. 大纲生成

大纲节点至少包含：

```text
outlineNodeId
parentOutlineNodeId
order
title
summary
sourceRefs
```

生成原则：

- 标题优先表达汇报对象能理解的主题；
- 摘要说明本章要解决的问题或输出；
- 大纲不暴露 57 项内部工作编号；
- 章节编号由 Presentation 根据层级和顺序显示；
- 标题、编号和顺序不能作为稳定身份；
- 语义未改变时，增量输出尽量保留 `outlineNodeId`。

---

## 7. 页面拆分

固定原则：

> 一页只表达一个核心结论，页面总数由内容自然产生，不设置固定页数。

### 7.1 通常需要拆页

- 同一页存在两个相互独立的核心结论；
- 不同结论需要不同证据或素材；
- 某项内容需要单独决策；
- 问题判断和解决方向各自具有完整论证链；
- 草案无法形成清晰讲解顺序。

### 7.2 通常不应拆页

- 只是同一结论的多项证据；
- 三至五个要点共同支撑一个判断；
- 指标、图表和说明属于同一问题；
- 仅为固定页数、平均章节页数或排版均衡。

### 7.3 单页建议组成

- 1 个页面主标题；
- 1 个核心结论；
- 2 至 5 个正文、列表、指标组或表格内容块；
- 0 至 3 个正式素材引用；
- 0 至多组独立讲解稿块；
- 对应的专业来源和证据。

以上是内容指导，不是排版限制。

---

## 8. 页面身份

`PageManifest` 负责页面身份、顺序和大纲归属。

固定规则：

- 页面使用稳定 `pageId`；
- 页面标题通过 `titleBlockId` 引用草案标题块；
- 页面标题正文不在多个文件中重复保存；
- 草案未生成时不创建空白草案文件；
- 页面移动、改名或改章节时保持 `pageId`；
- 页面拆分产生新页面和新 `pageId`；
- 初次生成时由投影规则形成页面；已有页面在外部编辑后如需合并，必须由人或当前 DSH Agent 明确触发，不由 `pre-design` 静默完成。

---

## 9. 第一版草案内容块

`pre-design` 第一版只生成五类基础语义内容块：

| 类型 | 用途 |
|---|---|
| `heading` | 页面主标题、副标题、内部小标题 |
| `text` | 核心结论、正文、说明、来源注记 |
| `list` | 并列要点、步骤和条件 |
| `metric_group` | 关键指标和指标说明 |
| `table` | 对比、分类和结构化数据 |

规则：

- 每页最多一个 `heading(role=page_title)`；
- 每页最多一个 `text(role=key_message)`；
- 列表项、指标、表格行列和单元格使用稳定 ID；
- 内容块只表达语义，不表达视觉几何；
- 时间线、流程图、鱼骨图、关系图和卡片组先用基础内容表达；
- 具体视觉形式由 Presentation 排版阶段决定；
- 最终字段名服从 Presentation Contract。

---

## 10. 独立讲解稿

讲解稿与页面展示内容分离。

至少表达：

```text
scriptBlockId
order
content
可选 estimatedDurationSeconds
可选内容块引用
可选素材引用
可选 sourceRefs
```

规则：

- 讲解稿不默认进入画面；
- 讲解稿说明讲述顺序、重点和口头补充；
- 时间使用结构化数值；
- 没有必要时可以为空；
- `pre-design` 可以生成初稿；
- 人或当前 DSH Agent 可以继续修改；
- 修改讲解稿不改变专业事实。

---

## 11. 内容性质

内容性质说明一段内容应被理解为什么，不是排版样式，也不是审批状态。

第一版语义：

| 内容性质 | 使用要求 |
|---|---|
| `fact` | 已确认事实，保留正式来源或证据 |
| `user_statement` | 用户提供信息，未核验时不得包装为事实 |
| `professional_judgement` | 有效专业分析形成的判断 |
| `assumption` | 明确为待验证假设 |
| `recommendation` | 专业建议，并说明依据或成立条件 |
| `decision` | 对应有效决策或 Gate 结果 |
| `missing` | 缺失或待确认信息，不形成确定性结论 |

规则：

- 由 `pre-design` Skill、人或当前 DSH Agent 填写；
- Presentation 只提供通用字段和可视化编辑；
- 标题等无须标记的对象可以不填写；
- 冲突信息不直接形成确定性结论；
- 过期、被否决或 supersede 内容不得重新输出。

---

## 12. 素材引用

- 草案只引用正式 `assetId`；
- 文件路径由 AssetManifest 管理；
- 页面可以表达主素材、辅助素材、背景素材和参考素材；
- 不保存素材坐标、尺寸或裁切；
- 未采用候选、缓存和临时文件不得进入正式草案；
- 场地边界、总平、红线和专业分析素材保留治理来源；
- 语义未改变时，增量输出尽量保留 `pageAssetId`。

---

## 13. 来源追踪

每个具有业务含义的内容对象可以保存通用 `sourceRefs`。

最小语义：

```text
provider
sourceProjectId
sourceRevision
objectIds
evidenceIds
可选 sourceSnapshotSha256
```

规则：

- 同一内容允许多个来源；
- 来源只用于追溯；
- 不表示内容所有权；
- 不定义自动刷新或自动覆盖；
- 不要求 Presentation 判断专业内容是否正确；
- 显示标题、页码和数组位置不能作为来源身份；
- 其他领域插件也可使用同一结构。

---

## 14. 正式草案准入

可以进入正式草案：

- 已确认事实；
- 用户提供信息，但必须保持来源性质；
- 有效专业判断；
- 显式假设；
- 专业建议；
- 已确认决策；
- 信息缺失，但只能作为待确认事项。

不得进入正式草案：

- 已过期对象；
- 被否决结论；
- supersede 内容；
- 无法解释来源的专业断言；
- 未采用候选素材；
- 为凑页数生成的内容；
- 排版占位文案。

---

## 15. 输出时机

采用“持续准备、节点输出”：

```text
专业工作流持续推进
        ↓
插件内部准备内容候选
        ↓
章节 Gate 通过、用户明确触发，
或当前 DSH Agent 在已授权任务中触发
        ↓
输出或更新标准项目文件
```

单个专业工作项变化不自动反复改写标准项目目录。

---

## 16. 外部修改保护

标准文件可能被人、当前 DSH Agent 或其他工具修改。

`pre-design` 保存自身上一次输出对象的语义 Hash：

```text
objectId → lastExportedSha256
```

再次输出时：

- 当前 Hash 与记录一致：允许更新；
- 当前 Hash 不一致：不覆盖，返回 `review_required`；
- 没有既有对象：创建；
- 不要求 Presentation 提供自动刷新、内容所有权或冲突状态机；
- 后续如何合并由人或当前 DSH Agent 决定。

---

## 17. 不生成排版

`pre-design` 不输出：

```text
LayoutPageDocument
字体、字号、字重、颜色
x / y / w / h
旋转和裁切
页面模板和版式名称
PPT 母版
HTML CSS
导出媒介参数
```

现有 legacy 报告代码第一版保留，但不作为新路径的结构事实源。

---

## 18. 验收标准

- 能从同一冻结专业状态生成大纲和草案；
- 不机械生成 57 页；
- 默认骨架不绑定具体项目类型；
- 不适用章节不出现；
- 每页至多一个页面主标题和核心结论；
- 五类内容块符合权威 Schema；
- 讲解稿独立；
- 内容性质正确；
- 页面只引用正式素材；
- 内容和素材具有可追溯来源；
- 不包含排版字段；
- 外部修改不被静默覆盖；
- Presentation 不需要理解专业对象；
- 人或当前 DSH Agent 是后续修改主体。

---

## 19. 当前状态

已冻结：

- 默认骨架和项目自适应；
- 57 项基础映射与受约束调整；
- 单页单核心结论；
- 五类内容块；
- 独立讲解稿；
- 内容性质；
- 正式草案准入；
- assetId 引用；
- sourceRefs；
- 外部修改保护；
- 不生成排版。

待 Presentation 最终确认：

- 七类 Schema 字段；
- ID 正式格式；
- 内容性质字段；
- sourceRefs 字段；
- TypeScript 类型；
- 验证器和标准包坐标。
