# Pre-design 大纲、草案与素材输出冻结基线 v2.0.0

## 0. 冻结结论

`pre-design` 第一版主体内容已明确到可以进入实现计划的颗粒度。

`pre-design` 负责把前期策划 57 项专业成果整理为符合 Presentation 权威标准的项目基本对象、大纲、页面清单、逐页草案、独立讲解稿以及已采用素材引用；不生成排版内容，不规定字体、字号、颜色、页面几何、页面模板或最终 HTML/PPTX/PDF 版式。

本文件只冻结 `pre-design` 自身职责和内容生成规则。Presentation 标准结构文件的具体字段、Schema、初始化器、验证器及跨仓消费方式，由 `presentation-tools` 统一定义，并通过仓库外独立交接文件反馈，不在 `pre-design` 仓库复制维护第二套标准。

## 1. 系统边界

第一版继续维持两个独立 DSH 插件：

```text
DSH
├─ pre-design 插件
│  ├─ 前期策划专业流程与 57 项工作流
│  ├─ ProjectBrief / Evidence / Assumption / Question / Gate / Revision
│  ├─ 项目标准目录初始化的执行
│  ├─ 原始资料导入与正式素材采用
│  ├─ 大纲和逐页草案生成
│  └─ 节点式同步到 Presentation 标准项目文件
│
└─ presentation-tools 插件
   └─ Presentation 标准、可视化编辑、排版和导出
```

本轮不合并仓库，不合并插件，不要求修改 `presentation-tools` 的界面或交互。

## 2. Pre-design 输出边界

`pre-design` 按 `presentation-tools` 的权威标准生成：

```text
ProjectManifest
ProjectRulesDocument
OutlineDocument
PageManifest[]
DraftPageDocument[]
SourceMaterialManifest
AssetManifest
```

`pre-design` 不生成：

```text
LayoutPageDocument[]
字体、字号、颜色
x / y / w / h
页面模板、PPT 母版
split / editorial / full-bleed 等版式
CSS 或最终媒介渲染参数
```

现有 legacy HTML/PPTX/PDF 路径第一版保留兼容，但不再作为新架构的长期事实源继续扩张。

## 3. 内容生成总流程

```text
57 项专业 State Object
        ↓
当前 pre-design Revision 的事实、证据、判断、假设和决策收敛
        ↓
8 类默认汇报主题的基础映射
        ↓
有约束的项目自适应调整
        ↓
OutlineDocument
        ↓
单页单核心结论的页面拆分
        ↓
PageManifest[] + DraftPageDocument[]
        ↓
独立讲解稿 + 已采用素材 assetId 引用
        ↓
Presentation 标准项目目录
```

禁止采用“一个专业对象对应一页”的机械映射，也禁止把 57 项内部工作流直接变成甲方汇报目录。

## 4. 默认汇报骨架

第一版采用“8 类稳定默认骨架 + 项目自适应”。

| 顺序 | 内部主题键 | 默认主题 | 主要内容 |
|---:|---|---|---|
| 01 | `project_brief` | 项目认知与任务 | 项目身份、启动背景、任务目标、服务对象、工作边界和基础约束 |
| 02 | `diagnosis` | 现状与核心问题 | 现状基线、需求缺口、核心矛盾、限制条件和问题优先级 |
| 03 | `opportunity` | 发展机会 | 政策、趋势、资源、市场、场景和价值机会 |
| 04 | `positioning` | 项目定位与目标 | 项目使命、目标体系、价值主张、定位和不可突破边界 |
| 05 | `program_product` | 产品与功能体系 | 功能组合、产品体系、使用人群、服务内容和使用场景 |
| 06 | `spatial_strategy` | 空间策略 | 总体结构、空间网络、分区、节点、尺度、场地分析和专业图件 |
| 07 | `delivery_model` | 运营、投资与实施 | 运营机制、投资测算、实施主体、分期、关键路径和风险控制 |
| 08 | `decision_next_steps` | 决策事项与下一步 | 已确认决策、待决事项、授权请求、成立条件和下一阶段行动 |

这些主题键是 `pre-design` 内部投影规则，不要求进入 Presentation 通用核心模型。

## 5. 项目自适应规则

默认 8 类主题不是强制固定模板：

- 不适用的主题省略，不生成空章节；
- 内容过多且包含多个独立判断链时可以拆分；
- 高度关联且共同服务一个核心结论时可以合并；
- 项目确有独立专业主题时可以新增；
- 所有新增、拆分、合并和省略都必须能追溯到专业对象和证据；
- 调整不得改变底层专业状态及其 Revision；
- 不得遗漏仍有效且影响决策的重要结论；
- 不得为了凑齐八章而重复内容；
- 不得把城市更新、滨水、文化街区等案例词写入通用默认骨架。

## 6. 57 项成果映射

采用“确定性基础映射 + 有约束的智能调整”。

### 6.1 基础映射

| 专业成果语义 | 默认主题 |
|---|---|
| 项目身份、启动原因、任务边界和基础条件 | 项目认知与任务 |
| 现状、问题、需求、缺口、矛盾和约束 | 现状与核心问题 |
| 趋势、政策、资源、市场和发展窗口 | 发展机会 |
| 使命、目标、定位、价值主张和非目标 | 项目定位与目标 |
| 功能、产品、服务对象、活动和使用场景 | 产品与功能体系 |
| 总体结构、网络、分区、节点、尺度和场地分析 | 空间策略 |
| 投资、运营、实施主体、分期、路径和风险 | 运营、投资与实施 |
| Gate 结论、已决事项、待决事项和下一步授权 | 决策事项与下一步 |

具体 57 项对象的映射由现有 Contract Registry、工作流元数据和受控映射表共同确定。

### 6.2 智能调整约束

DSH Agent 可以根据项目实际内容调整归属，但必须：

- 保留每个采用结论的来源对象、来源 Revision 和证据引用；
- 不得把过期、被否决或被 supersede 的内容重新纳入；
- 不得用排版需求改变专业结论；
- 不得为了视觉均衡制造无依据章节或页面；
- 对调整原因形成可审计记录；
- 相同冻结输入应产生确定性或可解释的稳定结果。

## 7. 页面拆分规则

逐页草案采用：

> 单页只表达一个核心结论，页面总数由内容自然产生，不设置固定页数。

### 7.1 通常需要拆页

- 同一页存在两个相互独立的核心结论；
- 不同结论需要不同证据或素材；
- 某项内容需要甲方单独决策；
- “问题判断”和“解决方向”内容量较大且各自具有完整论证链；
- 页面草案已无法形成清晰讲解顺序。

### 7.2 通常不应拆页

- 只是同一结论的不同证据；
- 三至五个并列要点共同支撑一个判断；
- 指标、图表和说明属于同一问题；
- 仅为了满足固定页数或平均章节页数。

### 7.3 单页建议组成

每页通常包含：

- 1 个页面主标题；
- 1 个核心结论；
- 2 至 5 个正文、列表、指标组或表格内容块；
- 0 至 3 个正式素材引用；
- 1 组独立讲解稿；
- 对应的专业来源和证据引用。

以上是内容完整性指导，不是排版限制。

## 8. 第一版草案内容块

`pre-design` 第一版只生成五类基础语义内容块：

| 类型 | 用途 |
|---|---|
| `heading` | 页面主标题、副标题或内部小标题 |
| `text` | 核心结论、正文和必要说明 |
| `list` | 并列要点、步骤和条件 |
| `metric_group` | 关键指标与指标说明 |
| `table` | 对比、分类和结构化数据 |

规则：

- 页面主标题使用 `heading`，并具有页面标题语义；
- 每页只能有一个页面主标题；
- 核心结论使用 `text`，并具有核心结论语义；
- 每页只能有一个核心结论；
- 列表项、指标、表格行列和单元格使用稳定 ID；
- 页面身份、顺序和所属大纲节点由 PageManifest 管理，避免在多处复制可冲突字段；
- 时间线、流程图、鱼骨图、关系图和卡片组不是第一版草案内容类型，先用基础语义块表达；
- 视觉形式由 Presentation 后续决定。

最终类型名称和字段名服从 `presentation-tools` 的权威 Schema。

## 9. 讲解稿

讲解稿与页面展示内容分离：

- 每一页可以有一组独立讲解稿块；
- 讲解稿说明本页如何讲、先后顺序、重点和必要的口头补充；
- 讲解稿不能被默认当作页面正文排入画面；
- 讲解稿可以引用同页内容块、素材和来源；
- 第一版不要求固定时长，但允许 Presentation 标准提供可选时间字段；
- 讲解稿修改属于 Presentation 内容 Revision，不等同于 `pre-design` 专业 Revision。

## 10. 素材引用

- 草案只通过稳定 `assetId` 引用正式素材；
- 草案文件不重复保存资产相对路径；
- 文件路径、MIME、Hash 和来源链由 AssetManifest 统一管理；
- 页面可以表达主素材、辅助素材或证据素材等语义角色，但不指定其几何位置；
- 未采用候选、缓存和临时文件不得进入正式草案引用；
- 正式场地边界、总平、红线和专业分析素材必须保留治理来源；
- 素材替换应尽量保持页面引用对象稳定，发生来源身份变化时必须显式记录。

## 11. 内容性质与正式草案准入

“内容性质”表示一段内容应被理解为事实、用户提供信息、专业判断、假设、建议、决策或信息缺失，不是排版样式，也不是审批状态。

第一版需要区分以下语义：

| 内容性质 | 是否可进入正式草案 | 表达要求 |
|---|---|---|
| 已确认事实 | 可以 | 作为事实表达，并保留证据或正式来源 |
| 用户提供信息 | 可以 | 明确来源为用户提供，未核验时不得改写为事实 |
| 专业判断 | 可以 | 必须来自有效专业对象，并尽量绑定证据 |
| 策划假设 | 可以 | 必须明确为待验证假设，不能包装成事实 |
| 专业建议 | 可以 | 明确为建议，并说明成立条件或依据 |
| 已确认决策 | 可以 | 必须对应有效决策记录或 Gate 结果 |
| 信息缺失 | 可以作为待确认事项 | 不得形成确定性结论 |
| 冲突信息 | 不直接形成结论 | 转为待核事项或阻塞问题 |
| 过期、被否决或已 supersede 内容 | 不得进入 | 下一次同步必须排除或标记失效 |

Presentation 标准结构必须为上述语义提供通用表达能力；具体代码字段名由 `presentation-tools` 决定，`pre-design` 不自行固定第二套字段。

## 12. 来源追踪

每个有业务含义的内容块必须保留通用来源引用，至少能够表达：

- 来源提供方；
- 来源项目；
- `pre-design` 来源 Revision；
- 来源专业对象；
- 来源证据；
- 必要时的来源决策或假设。

同一内容块允许由多个专业对象和多项证据共同支撑。显示标题、页码和数组位置不能作为来源身份。

`sourceRefs` 的最终字段名、基数和失效规则由 `presentation-tools` 权威 Schema 定义。

## 13. 同步时机

采用“持续准备、节点提交”：

```text
pre-design 专业工作流持续推进
        ↓
内部生成或更新大纲、草案和素材候选
        ↓
章节 Gate 通过，或用户明确执行更新汇报内容
        ↓
正式更新 Presentation Canonical 文件
        ↓
记录 pre-design Revision 与 Presentation Revision 的映射
```

规则：

- 单个工作项变化不自动制造大量正式 Presentation Revision；
- 未达到准入条件的内容不得静默进入正式草案；
- 正式同步基于同一冻结 `pre-design` Revision；
- 相同来源 Revision 的重复同步必须幂等；
- 已被 Presentation 人工修改的同一对象不得被静默覆盖；
- 冲突返回结构化结果并停止对应对象更新；
- 同步结果记录新增、修改、保留、冲突和失败对象；
- 同步不得创建或修改 `layouts/`。

## 14. 稳定 ID

`pre-design` 生成的大纲、页面、内容块、列表项、指标和素材必须使用 Presentation 标准定义的稳定 ID。

- 标题、页码和数组下标不能作为主键；
- 增量同步后语义未改变的对象应保留原 ID；
- 拆页、合并或替换时应产生明确的身份变更记录；
- `pre-design` 不自行定义与 Presentation 冲突的第二套 ID 格式。

## 15. 当前完成度

### 已冻结

- `pre-design` 与 `presentation-tools` 维持两个独立 DSH 插件；
- 项目创建时由 `pre-design` 执行标准目录初始化；
- 项目目录、原始资料、正式素材、强一致初始化和同步边界；
- 8 类默认汇报骨架及项目自适应规则；
- 确定性基础映射和有约束的智能调整；
- 单页单核心结论及页面拆分规则；
- 五类基础内容块；
- 讲解稿与展示内容分离；
- 页面只引用正式素材 `assetId`；
- 内容性质、草案准入和来源追踪；
- 持续准备、节点提交和 Revision 映射；
- 不生成排版内容。

### 尚待外部标准确认

- Presentation 标准目录的最终正式名称和版本；
- 七类 Canonical Schema 的最终字段；
- 最小合法实例；
- 初始化器和验证器接口；
- 稳定 ID 的最终格式；
- `sourceRefs` 和素材 lineage 的最终字段；
- Revision、冲突和跨仓消费的正式契约。

上述内容由 `presentation-tools` 单独反馈后，`pre-design` 再进入生产代码实现。
