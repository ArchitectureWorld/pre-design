# Pre-design 2.0.0 输出基线

## 1. 输出目标

Pre 将专业成果转换为可继续被人或其他 DSH 工具操作的标准项目目录，输出内容而不承担最终排版。

```text
57 项专业成果
→ 汇报叙事
→ 大纲
→ 页面清单
→ 逐页草案
→ 独立讲解稿
→ 原始资料与正式素材
```

外部 Contract `0.1.0` 只约束文件格式，不定义 Pre 的专业方法、工作流或产品版本。

## 2. 默认汇报骨架

Pre Skill 使用八类稳定默认主题：

1. 项目认知与任务；
2. 现状与核心问题；
3. 发展机会；
4. 项目定位与目标；
5. 产品与功能体系；
6. 空间策略；
7. 运营、投资与实施；
8. 决策事项与下一步。

执行规则：

- 不适用主题直接省略，不生成空章节；
- 内容过多时允许拆分；
- 高度关联时允许合并；
- 允许增加项目专属主题；
- 57 项专业对象通过确定性基础映射和受约束的项目自适应进入叙事；
- 不机械生成 57 页；
- 调整汇报结构不改变底层专业状态和来源。

## 3. 页面拆分

采用“单页单核心结论、内容自适应拆页”：

- 每页最多一个页面主标题；
- 每页最多一个核心结论；
- 不设置固定总页数；
- 不为满足页数或版式平均而拆页；
- 两个独立结论、独立证据链或独立决策事项应拆页；
- 同一结论的证据、指标和说明可以放在一页。

## 4. 草案内容块

Pre 2.0.0 生成五类基础语义块：

| 类型 | 用途 |
|---|---|
| `heading` | 页面标题、副标题和内部标题 |
| `text` | 核心结论、正文和说明 |
| `list` | 并列要点、步骤和条件 |
| `metric_group` | 指标及说明 |
| `table` | 对比、分类和结构化数据 |

讲解稿写入独立 `scriptBlocks`；正式页面素材通过 `pageAssets` 引用 `assetId`。

不得把整页内容压成一段 Markdown 或一个大字符串。

## 5. 内容性质

Pre 可为有业务含义的内容填写：

```text
fact
user_statement
professional_judgement
assumption
recommendation
decision
missing
```

该字段说明内容性质，不是审批状态和视觉样式。Presentation 等外部工具只读取和允许编辑，不替代 Pre 的专业判断。

## 6. 来源追溯

`sourceRefs` 至少记录：

```text
provider = pre-design
sourceProjectId = preDesignProjectId
sourceRevision = Pre Revision
objectIds = 专业对象 ID
evidenceIds = Evidence ID
sourceSnapshotSha256 = 可选快照 Hash
```

`sourceRefs` 只承担追溯，不授予自动覆盖、自动删除、所有权或同步治理能力。

## 7. 原始资料与正式素材

```text
source-materials/
= 项目最初输入的原始资料

assets/
= 已正式采用、加工或生成的汇报素材
```

固定规则：

- 原始资料默认复制，不移动、不覆盖；
- 原始文件字节原则上保持不变；
- 正式素材与原始资料分开保存；
- 候选、缓存和临时文件不进入正式 Asset Manifest；
- 同内容按 SHA-256 复用；
- 同名异内容使用跨平台安全路径；
- 每个正式文件记录稳定 ID、相对路径、MIME、`sizeBytes` 和 SHA-256；
- 不保存用户机器绝对路径；
- 不使用软链接、盘符、反斜杠或路径逃逸。

## 8. 内容与排版分离

草案只表达“讲什么”。以下内容不进入 `DraftPageDocument`：

```text
字体、字号、字重、颜色
x / y / w / h
旋转、裁切
页面模板和版式名称
PPT 母版
CSS
编辑器私有状态
```

`layouts/` 由后续可视化与排版工具管理，Pre 创建为空但不填写。

## 9. 稳定身份

- Project、Outline、Page、Draft、ContentBlock、Script、SourceMaterial 和 Asset 均使用外部 Contract 的稳定 ID；
- ID 首次创建后由 Pre 内部 Stable ID Ledger 持久化；
- 重复导出、改名、移动和排序变化不重新生成 ID；
- 新增、复制、拆分出的新语义对象使用新 ID；
- `projectSlug` 仅用于目录可读性，不是主键。

## 10. 完整性要求

导出成果必须通过锁定 Contract 的完整项目验证器，包括：

- 七类 Canonical 文档；
- ID 格式、唯一性和跨文件引用；
- Draft 路径和标题块引用；
- 讲解稿对内容块和素材的引用；
- Manifest 与实体文件的一致性；
- MIME、扩展名、字节数和 Hash；
- Unicode NFC、大小写折叠和跨平台路径冲突；
- 禁止未声明文件和缺失文件；
- 空大纲、空页面、空素材和空 `layouts/` 合法。

验证失败时不得发布成果目录或返回成功。
