# V14 参考设计理解与迁移 V2

## 授权与目标

用户在 2026-11-16 已明确批准上一轮 P0–P4 建议，要求执行开发、完成测试并同步远程，供 Claude 独立评审。本文件将该已批准方向落实为可实现的接口，不再重复设计确认。

目标：让 PDF/PPTX/图像参考先形成可追溯的设计知识，再编译为可执行组合版式，并用对照试排验证；解决 PPTX 绕过 V14 和只能套用五种布局的问题。

## 实现边界与选择

- 基线 `codex/web-v210@e9d78084776a30a0d674e00e4b69abf9ce3864c2`；独立分支 `codex/v14-reference-design-v2`，不合并主线、不部署生产。
- 保留 Node 24/Fastify/PostgreSQL/DSH、现有鉴权、原件隔离、资源版本、人工覆盖与端口约定。
- 对比了继续扩充 V14 提示、另建外部排版引擎、渐进扩展现有契约三条路线；沿用已批准的第三条，解析优先复用 PPT Master MIT 组件，仍由原生渲染器输出 HTML。
- JSON 是原生资源导入；PPTX/PDF/图像是参考分析。PPTX 不再默默走旧快速导入。原件保留受拥有者权限约束。
- PPTX 结构解析读取真实页面顺序、画布、主题、母版/版式引用、普通文本/图片/表格/图表及位置。实际预览用可用文档渲染器；能力缺失明确报告，不能把结构图假称为真实画面。
- PDF 分页保留页码/覆盖限制；DOCX 若无页面渲染能力，明确仅文本，禁止伪称视觉识别。

## 分析工作流

`reference-workflow.mjs` 的 `runReferenceWorkflow({jobId,payload,images,policy,signal,onEvent,runModel,skill})` 负责有参考资料的分阶段处理：

1. 服务端建立文件/页面清单，含文件 SHA256、页码、提取事实及覆盖范围。
2. 每批至多六张页面图像进行观察分析，形成页面类型、图文结构、密度和证据。失败不回退到默认套件。
3. 综合观察生成 `pre-design.reference-profile.v2`：意图、设计系统、页面原型、规则、证据和局限。区分 extracted / observed / inferred / user。
4. 基于 Profile 编译 `pre-design.layout-package.v2`，不自动增加默认五模板。每种布局关联原型和证据；无充分证据的样式不伪称来源。
5. 保存候选、Profile 和逐阶段实际调用收执，用户可查看分析及原参考对照。纯文字修改/讨论沿用简洁路径，已有 V2 Profile 在修改时保留且版本化。

## 资源与渲染契约

兼容 V1，新增 V2 声明式组合版式。V2 画布不固定 16:9；`layouts[].kind='composition'`，slots 保留 role/rect，增加 id、index/range 和受限样式用于多图、多文本区、表格、图表、时间轴/关系图等组合。禁止资源提供 HTML/CSS/JS 执行代码。布局能力匹配实际内容；不适合时明确拒绝，不能丢弃图文数据来套版。

`designProfile` 位于 V2 package，包含可共享的规范与来源指纹/页码；不包含原文、截图、原件路径、项目图片或业务数据。原始观察与文件 ID 留在拥有者的 job 分析记录。

V08 读主题和设计系统，V09/V10 按原型/内容选页，V11 原生组合渲染，V12/V13 沿用版本/覆盖逻辑。Q07 检查实际 DOM 溢出、缺图和内容覆盖；Q05 通过原图与新样稿并排对照，由用户确认风格迁移。模型及几何检查均不伪称用户视觉确认。

## 验收

- 自动化覆盖 PPTX 真实路由、结构继承、分页证据、分阶段失败/取消、V1兼容、组合图表、数据完整性与来源权限。
- 代表页必须包含实际项目式的长标题、文字、地图/多图、表格、数据组合；合成数据明确标注。实际项目内容试排通过已有项目预览接口，不能把合成样例冒充真实项目。
- 视觉确认绑定资源内容哈希/版本/试排收执，修改后重新确认；服务器强制执行，不能只加 UI 复选框。
- 必须运行本地相关回归、实际浏览器检查；CI 对评审分支执行。真实供应商视觉效果若没有凭据，则单列为需目标环境验收，绝不伪称完成。
