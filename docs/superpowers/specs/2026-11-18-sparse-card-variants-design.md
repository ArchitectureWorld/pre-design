# 少内容无图卡片变体

用户目标是看得懂真实套用效果，并非还原每个原件字段。沿现有 V14、Native Compiler、资源版本、矩阵与原文预览，不增独立资源体系。

现有已授权图像观察显示重复卡组，但实际稿件常只有标题、少量段落和要点、没有图片。强制20个局部文字映射既不能创造缺失内容，也不应复制正文填满。

## 方案与取舍
- 继续强制完整局部映射：保留密集结构，但真实少内容不能使用，排除。
- 模型补写缺失标题、图片：增加成本并可能虚构事实，排除。
- 采用明确标注的确定性平台派生无图卡片变体：保留源卡组节奏和设计色彩，直接消费现有段落和要点，不复制源内容、不填造事实。按用户已委托继续开发及父线程指示实施。

## 最小范围
1. 仅从授权、已验证图像观察识别2至4个平行等高近等宽卡组；一个可信页面、无嵌套组、无越界子项、无交叠组。每组有正文及标题/图片等支持卡片解释。不按文件、页码、业务名称识别。
2. 派生结构必须标记平台设计而非原件可选性/语义事实。无图、无独立文字槽；保留标题、所有段落、逐个要点。缺失、不一致、未知结构明确拒绝，不删除输入内容。
3. 同一 Native 编译与预览/实际渲染路径，旧版本不变，现有缓存不冒充新结果。不自动发布或改业务绑定。先私有只读真实页试排；后按现有版本审批路径集成。
4. 长内容仍以实际浏览器容量检查拒绝，不能静默截断。无图变体不能吞掉已有图片、表格或未映射 textBlocks。

## 验收
不同组数、无关ID/页码、不同位置比例正例；重叠/孤儿/嵌套/不等高/不同宽度/缺正文负例。真实授权页面、实际业务少内容只读试排，保留内容对照。原始密集版不回归。合成几何测试不代表真实视觉完成。

## 后续独立增量
冻结已选资源容量进入 V09 指定条目改写，避免整节重写丢失映射。现有正文PDF与版式成果PDF分开，不承诺尚未验证导出。

## 第二轮视觉修正
实际首页首轮在Chrome完整且无溢出，但细小文字悬在大片空白中，未通过作者视觉判断。第二轮增加独立纯段落变体，不复制段落成为points；简要卡片采用更清楚的72px标题、32px导语、36px要点层级，字符上限随之收紧。像素几何仍需真实浏览器确认，字体/版式断言不能替代美感评价。私有派生收执增加输出设计哈希，避免同观察不同派生输出混用验收。
