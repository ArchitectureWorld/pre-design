# Pre 2.0.0 可查数据源与分析链设计

日期：2026-09-12  
目标分支：`feat/pre-v2.0.0`

## 1. 目标

把现有 57 项专业工作流从“读取已有资料并生成结构化结论”升级为：

```text
项目资料 / 官方网站 / 官方开放数据 / 权威行业数据 / 专业计算
→ 采集
→ 来源记录
→ 字段提取
→ 标准化
→ 交叉核验
→ 确定性汇总/计算
→ LLM 专业解释与综合
→ 独立 Evidence Validator
→ Project State
→ 报告 / Presentation
```

最终每一个关键事实、指标和结论都必须能回答：

1. 数据从哪里来？
2. 什么时候取得？
3. 原始位置在哪里（文件、页码、表格、单元格、URL、接口或几何对象）？
4. 原始数据是什么？
5. 做了什么清洗、换算、汇总或计算？
6. 最终结论由哪些输入与方法得到？
7. 当前置信度、时效性和限制是什么？

## 2. 核心原则

### 2.1 数据源优先级

默认优先级：

```text
P0 项目正式资料 / 项目实测数据
P1 政府与法定机构官方数据
P2 政府认可的专业公共数据 / 国家标准 / 行业标准
P3 权威行业数据库、机构公开数据
P4 地图 / POI / 市场平台等辅助数据
P5 LLM 推断或假设
```

P5 永远不能伪装成事实。

### 2.2 Schema Valid 不等于 Fact True

State Object 通过 JSON Schema 只代表结构合法。事实是否可信，必须由 Evidence Validator 独立判断。

### 2.3 计算结果不由 LLM“心算”产生

凡可确定性计算的内容，例如：

- 面积、距离、覆盖率
- 人口、设施数量、密度
- 指标汇总
- 工程量 × 单价
- 现金流、NPV、IRR
- 多方案评分
- GIS/BIM 几何和统计

必须由专业工具或确定性函数产生。LLM 负责解释、比较和形成专业判断。

### 2.4 缺数据时停止伪造

缺少必要事实时：

```text
missing / unknown / assumption / blocked_external
```

不能生成看似真实的比例、评分、趋势、金额或排名。

## 3. 新增数据对象

### 3.1 DataSourceCatalog

统一登记系统允许使用的数据来源。

核心字段：

```text
sourceId
name
publisher
sourceClass
jurisdiction
authorityLevel
homepage
allowedDomains
accessMode
supportedDataKinds
freshnessPolicy
reliabilityGrade
notes
```

`accessMode`：

```text
workspace_file
web_page
web_search
api
manual_import
professional_tool
```

### 3.2 WorkflowResearchSpec

57 个 Workflow 每项必须有一份研究计划：

```text
workflowId
requiredDataPoints[]
optionalDataPoints[]
preferredSources[]
queryTemplates[]
extractionRules[]
normalizationRules[]
aggregationMethod
analysisMethod
crossCheckRules[]
freshnessRules[]
minimumEvidence
fallbackPolicy
outputClaims[]
```

这份 Spec 回答用户真正关心的问题：

> “这一项到底查什么、去哪里查、怎么汇总、怎么算、最后怎么得到结论。”

### 3.3 EvidenceRecord

在现有 EvidenceRef 基础上增加真正可审计的采集记录：

```text
evidenceId
sourceId
sourceType
sourceUri
sourceTitle
publisher
publishedAt
capturedAt
asOf
locator
rawValue
normalizedValue
unit
contentHash
reliability
claimClass
```

### 3.4 AnalysisTrace

每一个重要结论保存分析链：

```text
traceId
workflowId
claimId
inputEvidenceIds[]
inputObjectIds[]
methodId
methodVersion
parameters
calculationSteps
outputValue
confidence
limitations[]
```

这样最终报告中的结论可以反查到“来源 + 计算方法”。

## 4. 采集层

### 4.1 Workspace 资料

对当前 Workspace 中正式资料：

- PDF / Word / PPT / Excel / CSV
- CAD / GIS / BIM / 总平 / 红线
- 图片 / 视频

统一形成 Source Material + EvidenceRecord。

要求尽量保存原始定位：

- PDF 页码
- PPT slide
- Excel sheet + cell range
- 文档 section
- 图像 bbox
- GIS geometry ref
- CAD layer
- BIM element set

### 4.2 Web / API

建立 Research Provider 接口，不把具体搜索实现写死进 57 个 Workflow。

```text
ResearchProvider.search()
ResearchProvider.fetch()
ResearchProvider.queryApi()
```

每个 Workflow 只声明“需要什么数据和优先来源”，Provider 负责实际查询。

第一阶段只允许：

- 官方公开网页
- 官方公开 API / Open Data
- 无登录公开行业数据
- 明确允许使用的辅助地图 / POI 数据

不把需要验证码、登录绕过或不稳定抓取作为主链。

## 5. 来源等级与交叉核验

### A 级

项目正式文件、政府/法定机构原始数据、正式专业计算输出。

### B 级

权威行业机构、政府认可专业平台、公开标准数据。

### C 级

地图 POI、市场平台、公开商业数据库。

### D 级

新闻、二手转载、非权威页面。

### 推断

LLM inference / assumption，不能作为单独事实依据。

关键规则：

```text
高风险事实：至少 1 条 A 级证据
普通事实：至少 1 条 A/B 级，或 2 条独立 B/C 级交叉验证
来源冲突：不得静默择一，进入 conflict / needs_human
过期数据：按 freshness policy 标记 stale
```

## 6. 分析方法

### 6.1 事实型

例如人口、面积、道路、设施数量：

```text
采集 → 单位/时间/空间口径标准化 → 去重 → 交叉核验 → 输出指标
```

### 6.2 对比型

例如竞品、方案、地块：

```text
统一指标口径 → 同期数据 → 对比矩阵 → 差异 → 专业判断
```

### 6.3 空间型

例如服务半径、交通、设施覆盖：

```text
可信边界 + GIS/POI → 几何计算 → 覆盖/距离/密度 → 结论
```

### 6.4 规模型

```text
目标人群/需求 → 标准/基准 → 参数 → 公式 → 区间/敏感性 → 建议规模
```

### 6.5 投资型

```text
工程量 → 单价来源 → 基准日 → 税费/预备费 → 分项汇总 → CAPEX / 生命周期成本
```

LLM 不得直接补金额。

## 7. Workflow 执行链

正式目标：

```text
Workflow READY
↓
读取 WorkflowResearchSpec
↓
生成 Research Task
↓
自动采集 Workspace + Web/API + 专业工具数据
↓
形成 EvidenceRecord
↓
Evidence Validator
↓
确定性 Aggregation / Calculation
↓
AnalysisTrace
↓
LLM 生成专业候选 State Object
↓
独立 Quality + Evidence Gate
↓
auto_pass / auto_revise / blocked_external / needs_human
↓
Project State
```

## 8. 自动化原则

目标仍然是全自动为主。

人工只在以下情况进入：

1. 两个高等级来源相互冲突；
2. 正式边界、法定条件、投资等高风险事项；
3. 外部资料无法自动取得；
4. 自动修订达到上限；
5. 用户主动修改或锁定结果。

## 9. UI / 汇报侧最低可查要求

每个关键指标或结论至少可展开查看：

```text
数据来源
来源等级
数据时间
原始位置 / URL
分析方法
依赖数据
置信度 / 限制
```

汇报正文不要求显示所有技术元数据，但内部必须保留完整追溯。

## 10. 分阶段实施

### Phase A — 数据源与研究计划基座

- DataSourceCatalog Schema + Registry
- WorkflowResearchSpec Schema + Registry
- EvidenceRecord / AnalysisTrace Schema
- 57 Workflow Research Spec 文件框架
- Contract 校验与测试

### Phase B — 第一批真实来源

优先覆盖高价值公共数据：

- 项目资料
- 统计 / 人口 / 经济
- 规划 / 土地 / 政策
- 交通 / POI / 公共服务
- 气候
- 标准规范
- 造价 / 投资基础数据

### Phase C — Research Provider 与自动采集

- Workspace provider
- Web search / fetch provider
- API provider
- 专业工具 provider
- Evidence capture / hash / locator

### Phase D — 独立核验与计算

- Evidence Validator
- freshness / conflict / authority checks
- deterministic aggregation
- AnalysisTrace
- Workflow quality 接入真实 Evidence，不再只依赖 Agent 自评

### Phase E — 57 项全覆盖与真实项目回归

每个 Workflow 必须有：

```text
查什么
优先去哪里查
备用来源
怎么提取
怎么汇总
怎么算
怎么核验
缺失怎么办
最后形成什么结论
```

并使用真实项目做端到端回归。

## 11. 验收标准

最终任取一个关键结论，例如：

> “片区 65 岁以上人口占比较高，养老设施服务不足。”

系统必须能完整返回：

```text
人口来源：官方人口统计 / 普查
设施来源：官方公共服务数据 + 允许的 POI 辅助数据
数据时间：YYYY-MM-DD / 统计期
采集位置：URL / 表格 / 页码
原始值：...
标准化值：...
分析：老龄人口比例 + 养老设施数量 + 服务半径 + 人均指标
方法版本：...
结论：...
置信度：...
限制：...
```

如果这条链不能还原，该结论不得被标记为完全可信的 `auto_pass`。
