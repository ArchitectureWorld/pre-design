# Pre 2.0.0 工作区根目录与 UI 恢复设计

- 日期：2026-09-04
- 状态：approved-for-implementation
- 开发支线：`feat/pre-v2.0.0`
- Pre 版本：`2.0.0`
- Presentation Contract：`0.1.0`

## 1. 目标

将 Pre 2.0.0 从“Session 绑定项目、用户级公共目录输出”调整为默认的“DSH Workspace 绑定项目、Workspace 根目录即标准项目根目录”，同时保留现有 57 项流程、命令、Agent Tool、报告导出、Presentation Contract 校验和历史兼容能力。

## 2. 固定使用模型

```text
一个 DSH Workspace（SessionHeader.cwd）
= 一个项目总文件夹
= 一个 Pre 项目
= 一套 Presentation Standard Project Directory 0.1.0

同一 Workspace
├─ Session A
├─ Session B
└─ Session C
   共同使用同一个 Pre 项目
```

Workspace 根目录直接包含：

```text
project.json
rules.json
outline.json
pages/
source-materials/
assets/
layouts/
```

不再默认生成 `~/.dsh/presentation-projects/<projectId>-<slug>/` 这一层。Contract 中推荐的 `<projectId>-<projectSlug>` 目录名不是身份事实；当用户设置的 Workspace 文件夹名称不同，`project.json` 仍是权威，Contract 只产生非阻断 warning。

## 3. Workspace 识别

Host 以当前 DSH Agent Session 的不可变 `SessionHeader.cwd` 为 Workspace 路径来源，并执行：

1. 必须是绝对路径；
2. 必须存在且为目录；
3. 使用 `realpath` 作为唯一比较键；
4. 不接受符号链接逃逸；
5. 没有 `cwd` 时，UI 创建和 Workspace 模式同步明确失败。

为保留既有自动化测试与显式部署能力，仅当调用方没有 Session `cwd` 且明确配置 `PRE_DESIGN_PRESENTATION_PROJECT_ROOT` 时，继续允许旧的父目录 + `<projectId>-<slug>` 兼容模式。正常 DSH UI 路径永远优先使用 Workspace 根目录。

## 4. 一 Workspace 一 Pre 项目

`PresentationProjectBindingRecord` 增加内部字段 `workspaceRoot`。它不进入 Presentation 标准目录。

约束：

- 一个规范化 `workspaceRoot` 只能绑定一个 `preDesignProjectId`；
- 一个 `preDesignProjectId` 只能绑定一个 `workspaceRoot`；
- `/preplan-presentation-sync --probe` 只探测并恢复绑定，不写标准项目；
- 同一 Workspace 的新 Session 通过 probe 自动绑定已有 Pre 项目；
- UI 新建流程先 probe，已有项目时不再执行 `/preplan-new`；
- 新 Workspace 才创建新 Pre 项目；
- 手工切换 Session 后，执行同步或 UI 启动会恢复 Workspace 项目。

## 5. Workspace 根目录写盘

现有 Writer 的“完整目录原子替换”不能直接用于项目总文件夹，否则会破坏用户资料。因此增加 Workspace Writer：

1. 在 Workspace 同级创建 staging；
2. 复用现有 Contract Adapter 与 Writer 生成一套完整、已校验的候选标准项目；
3. 只管理并替换：
   - `project.json`
   - `rules.json`
   - `outline.json`
   - `pages/`
   - `source-materials/`
   - `assets/`
4. 永不替换：
   - `layouts/`
   - Workspace 中其他用户文件与目录；
5. 提交前比较 Pre 上次导出的托管文件 Hash；
6. 外部修改默认拒绝覆盖；
7. 备份托管路径后逐项原子替换；
8. 对最终 Workspace 根目录再次执行 Contract 全量校验；
9. 任一步失败时回滚托管路径并清理 staging；
10. 成功后只保存托管文件 Hash。

首次同步时，如果 Workspace 已存在同名 Canonical 文件或保留目录但没有 Pre 管理账本，必须拒绝静默接管；用户明确 `--force` 后才能采用。

## 6. 历史输出迁移

- 未成功发布过的旧绑定可自动改绑到当前 Workspace 根目录；
- 已成功发布到旧公共目录的项目，首次迁移到 Workspace 根目录必须显式 `--force`；
- 旧目录保留，不自动删除；
- Stable ID、Pre Revision 与 Presentation Project ID 保持不变。

## 7. UI 刷新恢复

新建面板的输入草稿使用浏览器 `localStorage`，按规范化 Workspace 路径分区：

```text
pre-design:v2:workspace-draft:<workspace-key>
```

持久化：

- 一句话项目描述；
- 可编辑项目名称；
- 名称是否被手工编辑；
- 人工/自动模式；
- 标准/扩展报告；
- 概念图预算。

规则：

- 同一 Workspace 下不同 Session 共用草稿；
- 不同 Workspace 相互隔离；
- 页面刷新和面板关闭后恢复；
- 创建并完成标准目录同步后清除；
- JSON 损坏或字段非法时安全回退为空表单；
- 没有 Workspace 时禁止启动并给出明确提示。

## 8. 打开项目文件夹

新增：

```text
/preplan-open-project-folder
```

以及 UI 按钮“打开项目文件夹”。

它打开当前 Workspace 根目录，而不是旧的全局 Presentation 输出目录。支持 Windows `explorer.exe`、macOS `open`、Linux `xdg-open`；路径只来自已校验的 Session Workspace，不接受用户传入任意路径。

## 9. 不变内容

- 不修改 Presentation 0.1.0 Schema；
- 不修改 `presentation-tools`；
- 不新增支线；
- 不改变 Pre 2.0.0 产品版本；
- 不删除旧 HTML/PPTX/PDF 能力；
- 不把 Workspace、Session、Gate、Revision、恢复记录写入标准项目目录；
- 不改变 `sourceRefs` 仅用于追溯的边界。

## 10. 验收

- Workspace 根目录直接通过 Presentation Contract 0.1.0；
- Workspace 其他文件与 `layouts/` 保持不变；
- 同一 Workspace 的多个 Session 解析为同一 Pre 项目；
- 重复同步 Stable ID 不变；
- 页面刷新后表单输入恢复；
- 成功创建后草稿清理；
- UI 与命令均能打开 Workspace 文件夹；
- Windows/Linux 路径测试通过；
- 全仓测试、构建产物测试与 GitHub Actions 全绿。
