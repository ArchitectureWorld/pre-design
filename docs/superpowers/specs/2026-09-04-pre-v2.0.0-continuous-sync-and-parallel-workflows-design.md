# Pre 2.0.0 持续同步与并行工作流设计

## 1. 目标

在不修改 Presentation Contract 0.1.0、不新增 Pre 支线的前提下，完成两项运行时升级：

1. Pre 每次形成正式 Revision 后自动更新当前 DSH Workspace 中的标准项目文件，使 Presentation 能持续获得大纲、草案、讲解稿和正式素材，而不是长期停留在初始化空骨架。
2. 自动模式不再机械串行执行全部 57 项；按既有依赖图计算 Ready Set，同一波最多启动 4 个专业 Subagent 并行分析，再由中央提交队列串行写入 Project State。

## 2. 固定边界

- 开发支线固定为 `feat/pre-v2.0.0`，不得新增支线。
- Pre 产品、插件和包版本保持 `2.0.0`。
- Presentation Standard Project Directory 保持 `0.1.0`。
- 不修改 Presentation Schema，不向 Canonical 文件写入 Pre 私有运行字段。
- 不静默覆盖 Presentation 或人工对 Pre 托管标准文件作出的修改。
- Subagent 只能分析并返回候选结果，不能直接写 Project State、确认 Gate 或写标准项目目录。
- 所有 Proposal、Revision、Workflow 状态和 Gate 写入继续由 Pre 中央服务串行执行。

## 3. 旧目录迁移

旧版可能已经把标准项目写入：

```text
~/.dsh/presentation-projects/<projectId>-<slug>/
```

当前项目则以 DSH Workspace 根目录为目标。两者不同时，普通同步必须返回：

```text
PRE_DESIGN_WORKSPACE_MIGRATION_CONFIRMATION_REQUIRED
```

并明确提示用户只需执行一次：

```text
/preplan-presentation-sync --force
```

该操作只确认把 Pre 托管标准文件迁移到当前 Workspace；旧目录不自动删除，Stable ID、Presentation Project ID 和 Pre Revision 保持不变。

## 4. Presentation 自动同步

新增项目级 `PresentationAutoSyncService`：

```text
Revision 正式提交
→ 将项目标记为 pending
→ 750 ms 项目级防抖
→ 读取最新 Revision
→ 生成最新标准项目快照
→ Contract 0.1.0 全量验证
→ 安全写入当前 Workspace
```

连续多个 Revision 合并为一次最新 Revision 导出。同步期间若又产生新 Revision，当前写入完成后继续追平最新 Revision。

自动同步失败不得回滚已经确认的专业 Revision。失败状态必须保留并显示为：

- `migration_required`：旧目录迁移需要用户执行 `--force`；
- `external_changes`：Pre 托管标准文件被外部修改，需要用户审查；
- `error`：其他写入或验证错误；
- `pending` / `syncing` / `synced`：正常生命周期。

触发点：

- 自动 Proposal 正式提交；
- 人工确认 Proposal；
- 正式采用或替换视觉素材；
- 场地边界正式确认；
- Gate 决策；
- 并行 Ready Set 一波完成；
- 全流程无剩余 Ready 工作项。

Gate 和批次结束使用 `flush`，普通 Revision 使用防抖 `request`。

## 5. 并行工作流

`WorkflowRuntime` 增加稳定有序的：

```text
ready(projectId)
running(projectId)
```

自动模式且 `spawn` Subagent Provider 可用、没有遗留 running 工作项、Ready 项不少于 2 时，协调器使用并行路径：

```text
取前 4 个 Ready 工作项
→ 逐项标记 running
→ 启动 1～4 个一次性 spawn Subagent
→ 并行生成结构化候选 State Object
→ 按 Workflow 固定顺序进入中央提交队列
→ 逐项 Schema 校验
→ 逐项创建 ProposalEnvelope
→ 逐项按最新 Revision 正式提交
→ 逐项标记 confirmed
→ 检查并自动确认已经 Ready 的 Gate
→ 合并执行一次 Presentation 同步
```

Subagent 使用父 Session 当前模型路线，不固定替换模型；`maxDepth=1`，工具列表为空，收到的上下文只包含：

- 当前项目身份；
- 当前工作项描述；
- 目标 JSON Schema；
- 目标对象结构示例（只作字段结构参考，禁止复制示例事实）；
- 该工作项实际需要的上游对象快照；
- 不得捏造和必须显式记录缺失信息的规则。

并行分析结果无论先后完成，中央提交顺序都保持 Contract Workflow 顺序，从而避免 Revision 冲突和非确定性。

任何子任务失败只阻断对应 Workflow，并保留可诊断原因。没有并行 Provider、人工模式、只有一个 Ready 项或存在遗留 running 项时，继续使用现有主 Agent 串行路径。

## 6. UI 状态

前期策划状态卡增加一行明确的 Presentation 状态：

```text
Presentation：已同步 Revision 11
Presentation：等待同步（Pre 12 / 已同步 11）
Presentation：正在同步 Revision 12
Presentation：需要迁移；执行 /preplan-presentation-sync --force
Presentation：检测到外部修改，未覆盖
Presentation：同步失败：<原因>
```

该状态来自 Pre 内部 Binding 和自动同步服务，不写入 Presentation Canonical 文件。

## 7. 验收

- 旧目录迁移错误给出可直接执行的 `--force` 指令。
- 连续 Revision 触发被合并，最终导出最新 Revision。
- 自动同步失败不影响专业 Revision，并在 UI 可见。
- Ready Set 最多 4 个 Subagent 并行分析。
- 中央提交始终串行且顺序稳定。
- 同一 Workflow 不重复运行；遗留 running 工作项仍可按旧路径恢复。
- 自动 Gate 只在 Gate 已 Ready 且自动授权有效时执行。
- 人工模式与所有现有命令、HTML/PPTX/PDF 输出保持兼容。
- 最终通过定向测试、TypeScript、全仓回归、构建产物测试和 Git diff 检查。
