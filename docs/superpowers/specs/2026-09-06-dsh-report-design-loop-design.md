# DSH 内生汇报设计闭环：跨插件设计规格

日期：2026-09-06

状态：跨插件方向已获用户确认；本书面规格待复核。仅设计文档，尚未实施、测试或部署功能。

## 1. 目标与交付边界

由运行在 DSH 中的现有 Agent 完成“读取前期成果 → 汇总分析和组织页面 → 选择／补齐素材 → 排版 → 查看真实页面图 → 返修 → 受控保存”。Codex 负责开发、测试和部署这些能力，不替 DSH Agent 编写真实项目的逐页文案、坐标或成品布局。

Presentation / Report Studio 是 Agent 使用的内容、素材、排版和审阅工具。保留内容与布局的数据分离，但不再把设计职责一并隔离掉。57 个前期工作项完成，只表示前期数据生产完成，不表示汇报已编排或排版完成。

本次交付是一个跨 Pre 与 Studio 的完整能力，不新增仓外设计 Agent、不更换当前会话模型、不另建通用演示文稿系统。原有大纲／草案编辑、视觉生成、Proposal 和布局存储均优先复用。

### 必须保留

- Reference 原件只读；不重新运行已完成的 57 项，不修改模型或认证配置，不停止 Tailscale。
- 保留全部原成果、草案全文、讲稿、素材来源、批注和审阅历史。
- 少潭河现有手工第 1 页不能覆盖；该限制通过运行时选择的稳定 pageId 和保护清单实现，不把“第 1 页”硬编码到通用产品。
- 其余已有页面不因升级自动重排。用户明确选择范围后，才生成修改候选；不预设总页数和合并数量。
- 不新增 Git 分支，不强推，不使用强制同步；交付补丁同步回对应现有远程分支，并验证源码、包和部署的一致性。

### 不在本轮范围

- 全新 PPTX 导出引擎、视频剪辑器、CAD/BIM 转换器、任意 HTML/CSS 生成执行、模型迁移、无人值守调度。
- 用 AI 图片替代法定红线、现场照片、审批文件或真实统计资料。
- 把之前 Codex 制作的六页样稿、其坐标或截图作为 DSH 产品能力验收结果。

3. 建立与正式能力相同的可重建基线，特别验证 worker、auto-apply 与现有 review 的行为未回退，再叠加本轮能力。
4. 如果无法恢复任一增量的对应源码或无法验证其行为，暂停 Studio 编码／部署并报告差异，不用旧包代替。

以上提交值是本次只读核验记录，不是以后发布时可直接沿用的动态状态；发布前重新核验远端、工作区和正式版本。

## 3. 方案选择与职责

选用“现有 DSH 主 Agent + 受控 Studio 设计工具”。仅补提示词无法接入布局和图片；新建仓外设计流水线则不能满足用户的运行环境要求。

| 部件 | 负责 | 不负责 |
| --- | --- | --- |
| Pre | 57 项工作流约束、成果来源、汇报任务路由、专业表达与事实规则、复用视觉生成服务 | 写 Studio 私有布局、替用户确认 Gate、覆盖 Studio 草案 |
| DSH 当前主 Agent | 汇总分析、合并／拆分建议、选图、设计候选、查看预览和返修 | 绕过工具直接改标准文件、冒充审批人、擅自切模型 |
| Studio | 当前草案与素材上下文、设计规则资源、候选与 Proposal、真实渲染、校验、版本保存 | 替 Agent 作项目结论、用固定模板自动宣称设计完成 |
| 宿主权限与现有审阅机制 | 会话身份、页面范围、受保护对象、人工确认和合法自动应用 | 信任 Agent 自报的授权、身份或审核通过标志 |

现有 `isolated-worker` 的大纲／草案批注流程保持兼容。本轮视觉设计走主会话工具结果；不把另一套设计模型塞入 review worker，也不把 worker 的 JSON 文本当作看图证据。

## 4. 任务路由与设计规则

### 4.1 明确区分两类任务

调整 `src/prompts/preplanning-system.ts`，保留全部 Pre 状态安全约束，但将“只处理 nextWorkflow”和“nextWorkflow 为 null 即停止”限定到前期工作项执行。

用户明确要求汇报编排、配图或排版时：先读取 Pre 的真实上下文以及 Studio 当前上下文，随后使用 Studio 工具处理已存在的成果；`nextWorkflow = null` 不再阻止这个独立的设计任务。硬阻断仍禁止对应的 Pre 状态变更；未知事实和未通过的条件继续标注，不能因进入设计阶段而被洗成确定结论。

没有用户设计请求时，57 项完成不自动启动付费配图或整套排版。插件缺失、项目绑定不符、素材不完整或视觉输入不可用时，分别说明缺口，不改用外部 Codex 代做。

### 4.2 规则必须随包部署并实际加载

Pre 提供专业内容规则；Studio 提供与渲染能力一致的版式规则和骨架元数据。短路由规则进入 systemPrompt，具体规则通过 `studio_get_context` 的设计上下文返回，并带版本号。不能仅存放在源码 docs 中，也不能依赖 Codex Skills、本机 Reference 绝对路径或先前聊天记忆。

从已授权参考中抽取通用图文比例和页面节奏，重写为插件自含资源；不复制参考项目的事实、古城叙事或固定色彩。当前项目规则优先决定风格和客户要求，事实与安全约束不得覆盖。

必须包含的设计行为：

- 汇报大纲是对成果的汇总分析，不是逐个数据字段拆一页，也不是压缩成几个摘要段落。
- 先定每页核心判断、支撑证据、主视觉和阅读顺序，再决定是否合并；同一论点且信息量适中的内容可合并，独立决策问题或过载页面应分开。
- 页面显式记录“展示哪些内容、哪些保留在讲稿／附录、哪些待补”，不要求全文逐字上版，也不允许删掉原草案和关键限定。
- 正文区域通常为页宽 28%–45%，一般不超过两个主要文字块；数据表／证据矩阵等结构化表达可例外，需保持可读。
- 骨架依据图片数量、纵横比、信息层级和图文面积选择，不能只按语义标签套模板；相邻同轮廓超过两页应检查并解释。
- 尽可能每页有相关视觉；可用大图作背景，但不是每页强制满版图。严肃数据／地图页可以图表或专业图件主导；纯文字／纯色页须有表达原因。
- 缩减上版文字、改变表达、换骨架或拆页优先于缩字。默认按 1600×900 画布等比使用：主标题不低于 36px，正文不低于 24px，图注和脚注不低于 16px；越界进入检查，不以无限缩字通过。
- 真实证据优先。地图、图纸、数据图表必须完整保留边界、图例和标注，默认 contain；允许 cover 的场景图仍须检查主体裁切和文字对比度。
- 规划、建议、假设、目标、待确认、未获批以及资金不同口径等限定不得在编辑表达时消失。不能拿通用图／AI 图冒充现场或实施完成。

这是一套设计指导与检查标准，不是宣称美学可以完全由固定比例自动判定。自动检查、Agent 看图结论和用户审阅分别记录。

## 5. 素材闭环

`PageVisualFillService.plan/generate/adopt` 和现有 VisualAgent 继续作为生图与治理基础。现有 slash command 面向 canonical finding，并不等于已给 Agent 接入，也不能直接拿 Pre 重建页替代 Studio 的当前页。

### 当前页身份与选图

Studio 设计上下文返回当前 pageId、草案内容 hash、来源映射、邻页、可用 `pageAssets`、全项目已登记素材候选及必要元信息。看素材需返回真实图片，不能只看文件名判断相关性。

所有排版使用的背景、主图、辅图、视频封面等必须先关联到当前草案页的 `pageAssets`，再引用布局。全项目素材不因被检索到而自动挂接到每页。用受控命令添加引用，不清空或重写已有页面素材库；不存在、不相关或无法解码的图片不能计为已覆盖。

视频、PDF、数据等原始资料保留可打开的当页引用。PDF／数据文件不能直接冒充背景图；需要图像时从有来源的有效预览／图件中选择。未实现或失败的预览明确列缺口，不用无关图片补足统计数。

### 缺图与生成

选择顺序是可追溯项目图件、已授权且相关的通用图、经明确授权的 AI 概念配图。授权不明的网图不自动采用；AI 不生成法定证据或带虚构数值的专业图件。

Studio 向 Pre 的已注册宿主服务提供受控的当前页视觉 brief，包含绑定项目、pageId、sourceStateHash、真实成果来源和表达意图。由服务端读取／核对该页，不接受 Agent 任意指定磁盘路径或伪造工作项归属。原 canonical finding 模式保持兼容；合并／新建页沿其真实来源映射形成独立的稳定请求身份。

Pre 复用原有固定视觉模型、质量检查、候选存储、幂等与取消恢复机制，返回候选身份及来源。Studio 的采用命令通过服务器侧适配器校验候选并导入，更新 Asset Manifest 和当页引用，使用当前 Studio revision 事务；不通过整项目 Pre 强制同步来挂一张图。

AI 候选生成不等于采用。默认保留现有人工采用边界；只有 DSH 当前任务存在宿主可核验的明确授权时，才可在该项目／页面范围自动采用。Agent 不能通过 `approved=true`、`actor=human` 或对话总结伪造授权。

跨插件采用先校验候选和源页，再记录 Pre 采用结果，最后提交 Studio 的素材与引用事务。每一步以稳定请求 ID 幂等；Studio 冲突时保留可恢复的已采用候选，重读后重试挂接，不再次生成、不宣称已挂页。返回状态区分 `candidate`、`adopted_unlinked`、`linked`。

展示中持续保留“AI 概念示意（非现场实拍）”或“通用参考（非项目现场）”说明和实际工具／许可／来源记录。生成失败、模型不可用、取消或页面已变更时停止当前页处理，保留原图与布局。

## 6. 受控布局候选与工具接口

沿现有工具扩展设计上下文、内容编辑和素材关联，新增小而专一的布局能力。下列是拟新增接口，不是当前已存在的工具。

| 工具 | 用途与输出 | 写入边界 |
| --- | --- | --- |
| `studio_get_context`（扩展） | scope=design；实际草案、讲稿、来源、邻页、规则、保护状态、渲染能力与版本基线 | 只读 |
| `studio_apply_commands`（扩展） | 复用大纲／草案 Proposal，加入受控素材关联及设计清单；支持保留来源的合并／拆分候选 | 按现有 Proposal 与授权模式，不直接写标准文件 |
| `studio_get_layout_context` | 当前布局、可用 sourceRef、素材及缩略图、当前设计范围 | 只读；不隐式 ensure 生成布局 |
| `studio_prepare_layout_candidate` | 整页 LayoutPageDocument、designIntent、sourceMapping、idempotencyKey → candidateId、candidateSha、diff、校验结果 | 仅保存隔离候选，不发布页面 |
| `studio_render_layout_preview` | 当前页面或指定不可变候选 → PNG 图像附件、渲染指纹、自动检查结果 | 不修改当前页面 |
| `studio_submit_layout_review` | candidateId、candidateSha、preview 指纹、Agent 观察及改动理由 → 可审阅 Proposal／现有授权下的应用结果 | 服务端校验权限、检查和版本；不是任意接受接口 |
| `preplanning_generate_page_visual` | 受控当前页 brief 身份 → 现有视觉服务的候选与真实图像 | 显式生成，权限与费用范围由宿主核验；不隐式采用 |

具体函数类型与文件分工在实施计划中固定，工具名称若需要调整必须同步 systemPrompt、注册、契约测试和打包验证，不留下仅在文档中的能力。

### 6.1 候选的不可变基线

候选绑定 `projectId`、`pageId`、`baseProjectRevision`、`baseLayoutRevision`、`baseLayoutSha`、`sourceStateHash`、`candidateSha`。无现有布局时用显式 null 基线，而不是假定某个文件 hash。身份、来源 hash、权限及 actor 均由宿主取得／重算。

`sourceStateHash` 覆盖实际用于此页的草案、讲稿映射、素材及文件哈希、项目规则；内容、图片、规则或布局变化使相关候选检查失效。幂等键相同但请求内容不同返回冲突，不能静默覆盖。

只接受现有契约支持的元素和安全 style 白名单，拒绝任意 HTML、脚本、外部 URL、路径逃逸、无效父子引用、未挂页的资产和不存在的 sourceRef。候选校验不只依赖当前宽松的 layout schema。

live 元素只用于真正可绑定的完整文本块、列表项、指标或表格单元。编辑后的摘要使用 detached 并保留真实来源映射，明确其不是自动同步文本；来源变化后标记需重审，不能冒称 live。讲稿和草案全文仍可回读。

合并／拆分通过受控内容 Proposal 创建新语义对象与新 ID，记录旧页／来源映射；原数据和审阅历史保留在版本链中。不能直接删除批注或重用旧 ID 掩盖新语义；受保护页不得成为修改或删除目标。

### 6.2 保存路径

复用 `createProposalFromAgent`／`acceptProposal` 的范围、风险和审核语义，扩展 layout scope 与命令，不把现有 `mutate` 或 `writePage` 裸露给 Agent 充当批准。

接受候选时，先锁定并重验项目和页面基线、来源、授权与检查，再复用 `LayoutPageStore.preparePage`、项目 `transactContent` 和 `publishPrepared`。项目 snapshot 内的 layoutRef 保持权威；中断后沿 `loadExisting`／`repairRef` 恢复索引。不可变对象或准备文件不等于发布完成。

预览、自动检查、Agent 审阅和批准必须绑定同一 `candidateSha`；任意修改使旧审阅无效。手工锁定／保护页无论 auto-apply 开关为何均不能自动覆盖。

默认新增布局操作需审阅，不扩大现有普通可逆 Proposal 的自动应用范围。若用户明确为这次设计任务授权指定页面自动应用，服务端验证项目、范围和有效期后才可执行；Pre AutomationAuthorization 不能借给 Studio 排版使用。

恢复旧布局应作为新的可审计事务引用历史对象，不重置整个项目或清空后续批注。测试必须证明最新 review worker 和原 auto-apply 行为维持原边界。

## 7. 真实渲染与 DSH 看图返修

抽取 Studio 当前 `layout-ui.js` 的纯画布渲染部分、素材 URL 解析和样式为共享 renderer，编辑器与后台预览共用。不能另写一套更好看的预览 HTML 来掩盖正式页面差异。

后台渲染冻结候选：使用本机可用 Chromium／Edge 的隔离隐藏进程，共用画布尺寸、CSS 和字体；等待字体及所有图片解码完成，关闭编辑选框／hover／缩放后截取画布。只开放该项目该候选所需素材，不接受任意页面 URL，不借用用户浏览器登录状态，不占用正式 3080 端口。所需控制依赖必须在 Studio 包中显式声明，不依赖 Codex 的浏览器插件或本机偶然可导入的开发库；缺浏览器时返回明确缺口，不在普通运行时自动下载。超时、取消和渲染结束均回收自有进程及会话临时目录；不终止用户浏览器。

复用 DSH 原生图像附件契约：`attachments.saveImage({ data, mediaType, name })` 后，工具 `output.render` 返回文字结果和 `{ type: 'image', attachment: imageRef }`。不把 base64 塞进 JSON 文本冒充图像输入。按当前 Session provider/model 的真实 inputModalities 检查图片支持；不支持时明确“视觉验收未执行”，不得切模型或标记通过。

输出指纹包含 candidateSha、PNG SHA256、rendererVersion、素材 hash、字体／画布信息和自动检查版本，支持证明保存对象就是所预览对象。缓存只复用完全匹配的指纹。

自动检查覆盖出界、文字实际溢出、图片解码／缺失、孤立来源、关键元素不可见、style 不支持和披露文字缺失。遮挡／对比度等机器难以可靠判断的情况作为检查提示，由 Agent 看图并记录观察；不能把所有元素交叠都当作错误，因为背景和文字本可叠放。

现有 renderer 不支持的字体属性、自定义裁切、箭头／路径不得被静默接受。首轮按真实支持能力设计；若表达必须依赖未支持功能，返回能力缺口或换合法表达，不把无效字段写入候选。

每页最多自动进行三轮“候选 → 看图 → 返修”迭代，仍有阻断则标记 `needs_review` 并保留候选和原因，禁止死循环。人工确认不能复用过期的预览。自动检查通过和 Agent 看图通过都不等于客户认可。

## 8. 进展可见、失败与兼容性

设计进展从现有持久候选／Proposal／版本记录聚合，不另造常驻任务调度器。按稳定 pageId 显示“编排待审、素材缺口、排版候选、已预览、需返修、待确认、已保存、受保护／跳过”。内容编排清单记录合并理由、来源覆盖和留在讲稿的内容；草案、素材和布局的状态分别显示。

统计至少区分：前期已完成工作项、汇报页面数、有可用相关视觉的页数、已生成布局候选页数、完成看图页数、实际保存页数。不能再用 57/57 或“有 layoutRef”冒充成品完成率。生成候选也不能计为正式页已更新。

默认一次顺序处理一页；当前主 Agent 中断后读取持久状态继续，不重生已确认的图片、不重复应用候选。大范围任务按用户选定的页集合推进，遇到版本冲突重读上下文，不强制覆盖。

读取项目、同步旧成果、打开文件夹和浏览 Studio 不产生设计写入或自动费用。旧项目、无布局页、已有手工布局及旧 review Proposal 均维持兼容。普通 Pre 同步继续尊重 Studio 外部修改，不为了补图或排版放宽 `confirmExternalChanges`。

## 9. 验收：必须证明 DSH 自己做到了

### 9.1 自动化与包级验证

- 路由回归：Pre 的 pending_review、Gate、blocked、模型限制保持；设计请求在 nextWorkflow=null 时可取得 Studio 设计上下文。
- 包级加载：从最终 tgz 实际安装后检查规则资源、工具 schema、图像输出注册和共享 renderer，不能只测源码 import。
- 候选安全：跨会话／跨项目、受保护页、假来源、未挂页图片、旧 revision、旧预览、同 key 异请求、非法 style、路径逃逸和重复提交均有负例测试。
- 保存／恢复：prepare 后、项目事务后、索引发布前的中断均可恢复；冲突不改变当前页；历史布局、讲稿、批注与 review worker 不回退。
- 素材：重复生成去重、取消／失败、采用未挂页的恢复、来源变化和素材缺失；无强制同步、无全章误挂图。
- 渲染：同一候选在编辑器与后台的画布、文本、图像及样式一致；损坏图片、溢出和不支持能力不能被当作通过；图像附件确实进入当前 DSH 模型消息。

### 9.2 DSH 宿主实测

先在保留来源和保护状态的少潭河隔离项目副本中验收，使用 DSH 原本配置的模型和正式插件加载方式。测试使用独立工作目录、项目和 Session 绑定；复制已存在的冻结成果，按契约映射身份及引用，不重新运行工作流，也不能让测试工具解析到原项目的可写目录。选择覆盖以下情况的一小组真实成果页：可合并文字页、地图／图纸页、资金／容量等数据页、无图页、有手工布局的受保护页。按内容选择而非写死六个样稿页号。

只向 DSH 提交自然语言任务与允许页范围，不提供 Codex 预先生成的文案、坐标、布局文件、candidates.json 或答案截图。由 DSH 真实调用工具并留下可追溯的任务／工具记录，至少证明：

1. 自行读取既有成果，给出有依据的页间合并／保留建议，并保留来源与完整讲稿。
2. 自行选相关素材；无图页走 DSH 现有生图服务或已授权通用图，采用后可在该页素材库看到。
3. 自行形成布局候选，图片通过原生工具结果交给当前 Agent，记录具体的视觉观察。
4. 至少一页有可追溯的“首次候选 → 真实预览 → 修改后新候选 → 新预览 → 保存”链；测试可要求根据预览优化，但不能外部编造缺陷或喂入正确坐标。
5. 保存后刷新 Studio 可看到同一内容和布局，版本／hash 对应；用户手工页面及原始成果未变。
6. 模型不具备视觉输入或生成不可用时明确失败位置，不用 Codex 的能力补齐后宣称通过。

事实回归针对少潭河现有来源核验，不作为写入模板：2,800m² 与 1,500m² 的不同口径；A 利旧失败不意味着 B 可直接建；容量为初步情景且不取消一级水源地隔离；44,200 万元与 28,500 万元不得用“含／不含利息”解释；移民配套验收且全部入住后才可腾退清库。以上均须重新对照实测时当前草案。

### 9.3 正式发布与完成判据

隔离验收通过后才备份正式包／项目并部署。重启时只操作经命令行和 loopback 监听确认的 DSH 进程，不停 Tailscale 或其他服务；不自动发送旧聊天输入框中的草稿。

正式验收重新确认项目、Session、Pre／Studio revision 和受保护 pageId。先验证工具注册与一小组已授权页面，不因插件升级批量覆盖 90 页；整套设计属于用户之后在 DSH 中选定的运行任务。

完成报告分别给出“自动化测试、DSH 实测、正式部署、远端同步”的结果。两个仓库各沿其现有分支正常提交／推送，比较远端 HEAD、本地 HEAD、tgz 文件 hash 和正式包文件清单。任一环节未完成都明确写未完成，不把本规格提交当作功能修复。
