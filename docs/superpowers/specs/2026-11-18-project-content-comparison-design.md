# 用当前页内容比较版式

## 意图与授权

用户强调普通人应直观看懂选用后大概是什么样，开发者仍需产品可控。root 已批准沿用现有只读预览及项目素材实现，不另等设计确认。开发在云端，部署保持4320。

## 最小方案

从项目当前单页打开版式库时，传入项目、当前稿件及页标识。矩阵与双击大预览复用现有 `/projects/:id/layout-preview`，所有候选以同一页真实内容和权限允许的项目素材渲染。独立打开版式库继续示例模式，并清楚标明。不得重新上传素材、调用外部模型、扩大共享权限。

选中不等于保存；浏览、放大、关闭、切换资源均不写稿件、版式资源或绑定。沿用现有明确‘选用此版式’动作及原文映射/保存门禁。未保存的版式编辑不得冒充已保存资源的真实预览；要么明确回到示例，要么提示先保存，不能悄悄忽略编辑。

缺少文字映射、字段、素材或容量不合的候选应显示可理解的具体原因，不使用示例内容偷换、不截断原文、不自动猜测分配。预览绑定到所选资源版本、稿件和页面；项目切换/重开/关闭后旧请求必须失效。保持缩略图矩阵、双击放大、批注与开发者控制。

## 考虑的方案

- 推荐并获root批准：复用已有项目只读预览，权限、素材、原稿和保存边界都有现成约束，改动最小。
- 暂不做：新建自由粘贴/上传素材池。会重复草稿、权限、保存体系，当前目标不需要。
- 不采用：仍用通用示例却称为真实效果，或者自动改写/丢弃不合版式的内容。

## 验收

同一真实合成项目页及其有权访问的测试图片在多个候选中可见；双击与缩略图内容一致。结构不匹配明确显示，示例模式可辨。取消/关闭/重复操作无写请求，切换项目或稿件不展示旧响应，其他账号图片不能访问。真实PG与Chrome端到端覆盖，同时保留现有批注和选择保存流程回归。合成测试不证明真实模型或审美。
