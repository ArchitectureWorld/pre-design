# Pre 2.0.1 Automation Policy Overlay Design

Date: 2026-09-12
Branch: `feat/pre-v2.0.1`
Baseline: `main@49140423e14f3d3abcf3815c9bdf68e8e5e26730` (Pre 2.0.0)

## Goal

Pre 2.0.1 runs end-to-end automatically by default. Human interaction is an optional override/edit path, not the normal mechanism that advances Workflows or Gates.

The legacy V0.6 contracts remain unchanged as historical business contracts. Pre 2.0.1 introduces an effective runtime automation policy overlay that supersedes legacy human-review defaults only while `mode=automatic`.

## Non-negotiable automation invariants

1. `risk=H` must never by itself produce `needs_human` or block automatic commit.
2. Risk controls evidence rigor, confidence threshold, cross-check strength and retry budget, not whether a person must approve.
3. Automatic Workflow proposals must use automatic validation semantics, not `human_review/pending_review` semantics.
4. A Workflow with trusted `auto_pass` quality may be automatically confirmed at any risk level when its automation authorization is valid.
5. A Gate with all required Workflows confirmed and trusted `auto_pass` quality must be eligible for automatic approval.
6. Exhausted automatic revision does not default to a person. It becomes `quality_unresolved`; explicit evidence conflict becomes `evidence_conflict`; unavailable external evidence remains `blocked_external`.
7. Human users may override or edit any result. That edit creates a new Revision and normal dependency invalidation/recalculation applies. Human action is not a standing prerequisite.
8. A real-world choice that cannot be made by the system is modeled as an external decision input, not as a generic human approval Gate.
9. V0.6 contract JSON is not rewritten to erase its historical human-review semantics.
10. CI must fail if an automatic-mode path reintroduces `risk=H => needs_human`, high-risk auto-commit rejection, or automatic `human_review` proposal intent.

## Effective policy

Runtime computes an `EffectiveWorkflowAutomationPolicy` from the legacy descriptor plus execution mode.

For `mode=automatic`:

- `humanApprovalRequired=false`
- `automaticCommitAllowed=true`
- `automaticGateAllowed=true`
- `humanInteractionMode=override_only`
- risk-aware default minimum confidence: L=0.72, M=0.80, H=0.88
- risk-aware default automatic attempts: L=3, M=4, H=5

For `mode=manual`, existing legacy review behavior remains available for compatibility.

## Quality dispositions

Automatic mode uses:

- `auto_pass`
- `auto_revise`
- `blocked_external`
- `quality_unresolved`
- `evidence_conflict`

`needs_human` remains only as a compatibility/manual-mode disposition and must not be emitted merely because a Workflow is high risk.

## Proposal semantics

Automatic execution still creates a ProposalEnvelope for revision, schema, authorization and idempotency safety, but it must not pretend that the proposal is waiting for a person.

Use existing V0.6 schema-compatible fields:

- `validation_intent = provisional_commit`
- `requested_state = confirmed`

The central Gateway then requires active automation authorization plus trusted `auto_pass` quality before confirming the State Object.

Manual mode keeps `human_review / pending_review`.

## Gate semantics

The Gate remains a machine quality boundary. In automatic mode it is approved by `system_service` under the project automation authorization once all required Workflows are confirmed and quality-ready. The human path remains available as an explicit override/manual mode, not as a mandatory checkpoint.

## Regression protection

Add dedicated automation-invariant tests covering:

- high-risk quality can `auto_pass`;
- high-risk automatic commit succeeds with trusted quality;
- all 57 Workflows, including H risk, can pass the automatic Gateway when quality and authorization are valid;
- automatic proposals do not use `human_review` intent;
- exhausted retries produce `quality_unresolved`;
- conflicts produce `evidence_conflict`;
- V0.6 source contracts are not modified by the overlay.
