# Linux Web V1 DSH P0 实施计划

**目标：** 验证 RFC 的固定版本 SDK 与现有专业核心能否在 Linux 上运行。
**依据：** `web/DSH_INTEGRATION_ROUTE_RFC_v0.1.md`；用户已要求开始执行。
**架构：** 独立 SDK 子进程、独立 DSH_HOME、独立测试 Workspace，先验证 P0-A，再迁移 P0-B。
**技术：** Node.js >=24.11、DSH 与 SDK 0.2.1-rc.5。

## 约束与验收

- 不改旁边已有 DSH 部署，不复用旧会话目录，不公开旧 Report Studio 端口。
- 没有真实模型结果不能称 Agent 闭环成功；单纯 SDK 握手不算 P0 通过。
- 关闭进程后恢复相同 session ID；记录工作目录和事件；失败返回非零退出码。
- 超时必须关闭子进程；恢复失败不能悄悄创建新会话。
- 只使用测试目录，不让 smoke 读取业务项目或密钥。
