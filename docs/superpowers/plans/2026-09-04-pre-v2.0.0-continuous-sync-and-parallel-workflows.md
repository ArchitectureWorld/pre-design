# Pre 2.0.0 Continuous Sync and Parallel Workflow Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Keep the Presentation standard project current after every confirmed Pre revision and execute dependency-independent workflows through at most four parallel Subagents with serialized commits.

**Architecture:** A project-scoped auto-sync service coalesces Revision events and publishes only validated Contract 0.1.0 snapshots. A parallel executor runs analysis in isolated one-shot `spawn` Subagents, then routes candidates through the existing ProposalGateway and WorkflowRuntime in deterministic serial order. Existing serial coordination remains the fallback.

**Tech Stack:** TypeScript, DSH 0.1.1-rc.2, Vitest, Cordis, `@deepseek-ai/dsh-subagent`, Presentation Contract 0.1.0.

**Spec:** `docs/superpowers/specs/2026-09-04-pre-v2.0.0-continuous-sync-and-parallel-workflows-design.md`

## Global Constraints

- Modify only `feat/pre-v2.0.0`; do not create another branch.
- Pre version remains `2.0.0`; Presentation format remains external Contract `0.1.0`.
- Never modify or duplicate Presentation Schema.
- Never silently force migration or overwrite externally changed managed files.
- Subagents analyze only; central Pre services own validation, proposals, Revision commits, Gate decisions and standard-project writes.
- Preserve the existing serial workflow path as a fallback.
