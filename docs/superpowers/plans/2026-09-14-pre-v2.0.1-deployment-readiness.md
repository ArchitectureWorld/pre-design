# Pre 2.0.1 Deployment Readiness Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn the current 57/57 traceable research foundation into a deployment-testable V2.0.1 research runtime with field-level Evidence locators, real official-page fetch support, independent evidence execution/validation, and automatic/manual Proposal tool routing that matches the Gateway.

**Architecture:** Keep `feat/pre-v2.0.1` isolated from `main`. Add a reusable selector layer shared by Workspace and Official Web providers, route provider execution through a source-scoped research execution service, and expose only validated evidence results to downstream runtime/tooling. Preserve automatic-first behavior: missing/blocked evidence fails closed as research status, not as mandatory human approval.

**Tech Stack:** TypeScript 5.9, Node 24.11 global `fetch`, AJV, Vitest, DSH tools/runtime.

**Spec:** `docs/superpowers/specs/2026-09-12-pre-v2.0.1-source-traceable-research-design.md`

## Global Constraints

- Only modify `feat/pre-v2.0.1`; do not touch `main` or historical V2.0.0 contracts.
- Keep product/package version `2.0.1` and Presentation Project Format `0.1.0`.
- Every EvidenceRecord must identify `workflowId`, `dataPointId`, source, exact locator, content hash, capture time and claim class.
- Official Web access must remain inside DataSourceCatalog allowed domains, including the final redirected URL.
- Binary PDF/Office/CAD extraction remains delegated to DSH attachment/material extractors; no OCR or guessed parsing in this provider round.
- Automatic mode must support `provisional_commit/confirmed`; manual mode keeps `human_review/pending_review`.
- No `auto_pass` claim may be based only on LLM self-report when this research execution path is used.
