# 基于资料的首轮章节梳理实施计划

**Goal:** 上传资料后先形成可追溯的11章草案，多轮澄清疑点，用户确认具体版本后才开放后续研究。

**Architecture:** 沿用现有原型首轮对话页和工作台。新增独立章节草案契约、版本记录及确认收执；模型仅能读取项目资料，结构化输出草案。专业核心对象和既有研究模块编号保持原身份，不将章节草案冒充已完成的专业成果。

**Tech Stack:** 现有 Fastify / PostgreSQL / DSH Worker / 原型 adapter。

**依据:** 用户当前明确指示及“前期策划分类”会话 6ae81dae-1c94-83e8-a52f-7e68d289177a 最新11章约定。延续此前执行授权，不另做界面设计审批。

## 契约

- 章节固定顺序：项目基本情况、城市与周边、项目发展方向、人群与需求、竞品与案例分析、场地现状、功能与项目内容、空间布局与建设方案、开发与运营、投资与实施、结论与建议。
- 每章包含本项目任务、适用性及理由、资料依据、缺口和依赖。第5章综合前4章并反馈第3章。三个研究尺度分别判断，不硬编码统一半径。
- 首先读资料，已有明确资料不重复询问。只问影响章节选择、研究边界或顺序的疑点；不把无法解析的原件说成事实。
- 草案版本与当前资料摘要绑定，确认必须指向最新版本及其摘要；新资料或新回答使旧确认失效。阻断性问题未澄清不能确认，允许明确记录后续补充的非阻断缺口。
- 后端拦截未确认的研究、成果生产及专业确认。草案确认只确认工作范围，不批准专业结论，不自动启动付费研究。
- 对话回答和草案保存在服务器，刷新可恢复；不运行旧原型固定问题队列。
- Web 4320、DSH HTTPS3080，原型 CSS 原样保留。已有真实资料、历史任务与成果保留。

## 重点风险

- 模型JSON无效、缺章或伪造资料引用必须拒绝保存为有效草案。
- 多页签过期确认、重复请求、运行中点击确认不得绕过版本约束。
- 用户资料中夹带指令不能授予写入或批准权限。
- 未解析CAD/RAR仍保留为缺口，图片元数据不等于影像内容识别。
- 新11章是策划流程目录；原7个报告生产入口不是11章完成能力，不能悄悄改名冒充迁移完成。

## 2026-11-04 资料充分性修正

用户反馈：V2将11章全部纳入，现有资料是否足够、用地性质和项目红线是否具备？

根因：旧契约仅记录章节适用性和折叠缺口，没有表达现阶段能力；确认目录后后端只检查已确认状态。

- [x] 4项关键条件分别记录：本次研究范围、项目红线/实施边界、现状与规划用地性质、规划管控线及适用条件。已支持的条件必须引用通过真实读取验证的内容，文件登记和影像元数据不能充当依据。
- [x] 每章增加当前能力、现在可做、暂不能做、启动条件。目录适用性与执行能力分开，历史水库管理范围不替代本项目红线。
- [x] 后端按专业模块真实含义关联新章节，提交及执行时复查条件；确认目录不解除缺资料限制。未就绪时普通问询保持只读。
- [x] 原型首屏直接显示4项条件及能力计数，章节摘要显示能力；任务图和研究选择器保留受限状态，原型CSS不变。
- [x] 少潭河真实模型生成新版待确认草案，复核原文/能力声明，LAN浏览器刷新验证。

执行边界：新11章与原62专业模块有明确任务映射，但报告生产/提案确认/批注修改尚无细粒度新章节对象绑定，因此采取全部11章就绪的保守检查。受限资料梳理可继续在首轮讨论进行；不能声称已具备逐条任务级的专业生产能力。
