# Pre 2.0.1 Automation Policy Overlay Implementation Plan

**Goal:** Correct Pre 2.0.1 so automatic mode is genuinely end-to-end automatic. High risk increases machine verification rigor instead of forcing human approval.

**Branch:** `feat/pre-v2.0.1`

**Historical constraint:** Do not modify the V0.6 Workflow/Gate contract JSON semantics merely to make automation pass. Apply a V2.0.1 effective runtime overlay.

## Task 1 — RED tests for automation invariants

Modify/add tests first:

- `tests/workflow-quality.spec.ts`
- `tests/automation-workflow-committer.spec.ts`
- `tests/proposal-gateway-all-workflows.spec.ts`
- `tests/automation-policy-overlay.spec.ts`

Required failing expectations before production changes:

- H-risk + complete trusted quality => `auto_pass` in automatic mode.
- exhausted automatic revision => `quality_unresolved`.
- evidence conflict => `evidence_conflict`.
- high-risk automatic commit is permitted when trusted quality and authorization pass.
- automatic proposal uses `provisional_commit` + `confirmed`, not `human_review` + `pending_review`.
- all 57 Workflows can auto-confirm when authorized and quality-ready.

## Task 2 — Effective Automation Policy

Create:

- `src/runtime/automation-policy.ts`

Modify:

- `src/contracts/types.ts`
- `src/contracts/registry.ts`

Expose an effective automatic policy without changing source V0.6 contracts. Risk defines minimum confidence and retry budget, not human approval.

## Task 3 — Quality semantics

Modify `src/runtime/workflow-quality.ts`:

- automatic mode never routes to human solely from risk;
- add `quality_unresolved` and `evidence_conflict` dispositions;
- use effective risk-aware confidence/retry defaults;
- preserve `needs_human` for manual/legacy compatibility only.

## Task 4 — Automatic commit semantics

Modify `src/runtime/automation-workflow-committer.ts`:

- remove high-risk automatic commit prohibition;
- use effective automation policy;
- emit automatic ProposalEnvelope semantics (`provisional_commit`, `confirmed`);
- keep schema/revision/idempotency/authorization/quality checks.

## Task 5 — Gateway + Gate

Modify `src/proposals/gateway.ts`:

- accept manual human-review envelopes only on manual path;
- accept automatic proposal semantics only when project policy is automatic;
- remove risk-based auto-confirm rejection;
- retain trusted `auto_pass` quality and authorization requirements.

Review `src/runtime/gate-service.ts` and `src/runtime/automatic-gate-approver.ts`; change only where required so quality-ready Gates auto-approve without a human checkpoint.

## Task 6 — Automation invariant CI

Add `pnpm test:automation-invariants` and run it in the V2.0.1 CI before full regression. It must fail on any future reintroduction of high-risk mandatory human approval in automatic mode.

## Task 7 — Documentation + HTML wording

Update V2.0.1 research design and source-audit HTML wording so “high risk” means stronger automatic validation, not mandatory human confirmation. Human is described as override/edit or genuine external-decision input.
