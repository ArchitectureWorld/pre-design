# 对外汇报与自动配图

正文采用 `compileClientReportOutline` 的共享内容：每个主题一页，以项目结论和至多三个要点说明。详细论证、原始条目及依据放在讲稿备注和 HTML 附录。Presentation 和 HTML/PPTX/PDF 使用相同主题及页面素材绑定，不能另走逐工作项纯文字摘录路径。

图片分为三类：

- 原始图像：校验实际字节与尺寸后，作为现状资料绑定相关页面；不推定拍摄日期、红线或比例。
- AI 概念场景：资源体验、推荐路径、产品组合、功能和空间意向产生明确生图任务。自动流程调用全局 image 类配置，检查生成结果后自动采用并同步到指定页面。标注 AI 概念示意，不能冒充实拍或规划批准方案。
- 资料图解：从本页实际策划条目构成要点图，记录源对象和版本；不得捏造统计、比例或因果关系。PDF/CAD 原件本身不算可显示图片。

自动完成顺序为：文本策划完成 → 配图规划 → 按授权调用真实模型 → 图片文件检查 → 自动采用 → 页面同步 → 同版本三种格式导出。暂停、版本变化或项目切换会阻止后续付费与采用。遗留生成请求先恢复原 child，不能自动重开不确定的付费任务。

生图提示从产品、功能及项目禁入条件提取场景要求，禁止项只作为排除条件。图片文件检查不等于语义审查；监督发现不合适的画面后，使用 `/preplan-visual-reject <assetId> <原因>` 留痕拒收并同步撤下，原图片文件及模型执行历史保留。相同任务不得恢复已拒图片，修订场景要求后才生成新的任务。

用户要求生图按需生成时，执行 `/preplan-visual-budget unlimited`，将当前授权的 `visualBudgetMode` 设为 `on_demand`。图像不受张数上限限制，也不占文本任务额度；原文本授权 ID 和计数保留。兼容旧的有上限模式，其通用额度、生图授权额度及项目累计预算仍在 class 任务预留时检查。错误保留未完成状态，不冒报完成。`.pre-design/visual-delivery.json` 保存页面需求和执行结果，`.pre-design/page-visual-fill.json` 保存实际图片任务与绑定。

报告复用必须同时匹配内容、素材哈希及编排版本，不能仅凭相同业务 Revision 复用旧报告。验收需检查实际页面图片加载、主文案和 HTML/PPTX/PDF 文件，而非仅检查工作项完成数。
