# 执行与配图错误隔离

本轮变更适用于所有 pre-design 项目，不修改项目原稿或专用 HTML。

- 自动模式的 `scope.maxModelTurns: null` 表示不限任务数量；保留数字上限的兼容能力、历史执行记录及独立生图预算策略。新增自动模式授权默认不限数量，已有授权必须有用户指令才调整。
- 子 Agent 类配置只保留主模型、备用模型及配置操作，移除实际执行记录区块。后台诊断记录保持完整。
- 单项工作流分析、提交或登记失败，不关闭其它 Ready 工作的并发补位；并发仍最多五个，提交仍串行。失败工作项及依赖它的后续项不冒充完成，单轮不重复派发失败项。
- 文案生成和成稿编辑同样逐章隔离错误，继续后续章节并保存成功检查点；有缺章时不发布不完整文案，汇总存入 `.pre-design/report-manuscript-errors/`。纠错重试仍有界，主动取消和版本变更仍生效。
- 场景转译允许原生汇报流程逐项隔离失败，后续批次继续；未成功转译的位置不使用原始抽象词充当有效图像需求。来源原则、合同分配等句子保留在完整引用语境中，不要求照片逐项展示。
- 图片恢复、素材读取、审图、检索、生图及采用失败均按项记录，继续其它可执行内容。成功结果和缓存保留；未知结果的原请求不重复提交。
- 配图错误保存在 `.pre-design/report-image-errors/<runId>.json`，最终缺口与错误汇总在 `report-image-gaps.json`，通过原生会话状态报告。已解决的错误也保留历史。
- 主动取消仍终止执行。项目版本变化不会向错误版本写入结果。全部可执行工作处理完后，尚有缺口的报告如实返回未完成；正式导出的图像与版式验收标准保持原要求。

回归覆盖后续批次继续、失败依赖隔离、原始缓存不变、有限重试、五项并发、用户取消及错误汇总通知。实机部署和新版 HTML 交付分别验收，不以测试通过代替导出成功。
