## 抽象后的内容契约

汇报是一个有论据的项目主张：**机会和条件 → 定位与取舍 → 产品与体验 → 空间和服务 → 启动与运营 → 投入及价值**。这是论证关系，不是统一页数或照搬参考目录。

1. **项目主张**：用一句可讨论的陈述明确项目要成为何种场所、面向谁、提供何种独特价值。区分现状事实、策划判断、拟议方案和测算假设。
2. **依据与解释**：事实、数据、案例、政策必须说明其对本项目选择的影响。记录“有一个字段”不等于完成分析。
3. **方案取舍**：必要时用相同维度比较可选方案，在正文展示为何选这一方案及什么条件会改变选择；不得只显示一个综合分数或“最优”结论。
4. **具体产品**：每个主导产品说明名称、客群、体验活动、场地载体/位置选择、建设或改造动作、规模依据或规模确定原则、运营方式。配套设施不应挤占主导体验；不得为了凑产品虚构资产或设施。
5. **空间落实**：总体关系、分区、重点节点、进出与游览线路、后勤与服务承载相互对应。缺底图时先用标明非地理图的关系表达，不能借 AI 画面伪造场地、红线或管网。
6. **启动方案**：交代为何先启动这一组产品、需要哪些最小设施、如何形成完整到访体验、谁运营、投入依据及后续扩展条件。只写“轻资产、分期推进”不合格。
7. **经营与投入**：展示谁投、谁营、向谁收费、收入如何形成、哪些属于公共服务投入；有可靠数值时展示口径、单位、公式和情景，无数值时说明决策边界，不能从参考稿补数字。

## 页级写作和图文分工

### 文字表达：直接陈述方案，而非记录讨论

参考稿的主体是“项目将形成什么”，而不是“团队分析过什么”。可借鉴的句法是：**具体对象 + 规划动作 + 使用体验、空间关系或经营作用**。产品名称可以直接成为标题；正文用设施、活动和服务内容解释它，不能只有“赋能、融合、标杆”等口号。

两处具体依据：PDF49以“台钓专区”直接命名产品，主张“台钓专业场地、优质鱼种配置、灵活配置满足不同赛事需求”，随后写赛事形式和称重、裁判、休息等配套；PDF75“入口景观标志”先交代位置，再写形象、尺度和游客远处可感受到的乐游属性。其文字组织是产品内容和设计作用，并非“已完成分析”“建议后续明确”。这些页的鱼种、工程尺寸与地点只属于参考项目，不转入其他项目。

以下仅示范句法，不构成少潭河的项目事实或业态要求：

| 不能作为汇报主体的表达 | 方案语言的表达方式 |
|---|---|
| 经讨论，建议后续明确展示空间的功能。 | 利用既有连廊布置可更换展板，让课程成果展示与日常通行共享空间。 |
| 接待规模需根据实际情况进一步确定。 | 拟采用预约分组，以可用活动空间、带领人员和单次服务时长共同限定接待量；现阶段不作固定容量承诺。 |
| 需进一步核实建筑是否可以利用。 | 在既有建筑具备合法使用与安全条件的前提下承载室内体验；条件未成立前，首期按室外活动组织。 |

转写必须保留资料的确定性：已有、拟议、假设与未成立条件不能混淆。影响选址、可建范围或经营方式的实质前提紧邻方案说明，不能全部藏到备注。来源索引、审批过程和重复免责声明另附。不要把原始字段中的问答、意见归属和过程记录原样搬上汇报页。

页标题指明对象或议题；主张句表达本页结论；正文解释方案、依据和影响；图表承担不可替代的证明或表达任务。不能把“本页介绍……”“后续需要填写……”作为可上版正文。图注说明来源和性质，详细过程与资料索引放在可查阅的依据记录。

| 页任务 | 正文要回答 | 合适的表达 |
|---|---|---|
| 机会/定位 | 为什么此地适合此方向、区别在哪里 | 主张＋关键依据；必要的市场/资源比较 |
| 现状/条件 | 现状是什么、意味着何种设计动作 | 实拍、真实底图、叠图；保留必要图例 |
| 产品/节点 | 谁在何处进行何种体验、建设什么 | 产品描述＋位置/现状＋针对该节点的意向图 |
| 方案比选 | 选项的差别和选择理由 | 同维度对比表或数据图，不能藏进备注 |
| 空间/游线 | 产品怎样连接、如何进入和运行 | 有依据的总图、节点图或非地理关系图 |
| 启动/运营 | 先做什么、主体和依赖是什么 | 分期清单、职责/经营矩阵、时序图 |
| 投资/收益 | 数字由何而来、关键假设是什么 | 可核对的表格和公式；区分测算与承诺 |

一页可以是产品详述、地图分析、比较表或短宣言，不强制“一句＋三点”。页数由论证和产品展开决定，不固定为 36 页或 125 页。不以图片覆盖率作为质量指标；把正文再画进 SVG 不算新增分析图。

## 不照抄的地方

参考中的“国内首个”、等级目标、政策适用和经营数据是该稿的陈述，不是其他项目事实。部分图片未充分说明来源；部分测算表缺当页来源、口径或回收公式，且密表可读性有限。应借鉴其产品—空间—经营—分期的连续关系，补足出处、假设和可读性。尤其不能把水上垂钓、坝体游览、村落商业或建筑改造移植到不具备条件的项目。

## 当前实现为什么失败，修正什么

旧 `compileClientReportOutline` 将业务对象的第一条字段截为 100 字，另外取三条 75 字要点；36 个专题各一页，全部表格进入讲稿；配图主要是同样的文字卡片和共用主题的概念图。这只能生成摘录，无法形成策划汇报。

修订采用独立且可追溯的汇报内容稿。配置的文本子 Agent 按上述论证角色撰写；内容稿记录来源引用、产品描述、正文表格和每页图像职责。Presentation 与 HTML/PPTX/PDF 读取同一内容稿。内容校验、真实模型生成及人工式阅读评价分开记录，不用技术检查通过替代“文案可用”。

真实审读表明仅让模型从专业字段起稿仍会继承大量管控措辞，因此生产链路增加必经的成稿编辑。各章在同一表达规范和全稿主题下分别编辑，使用独立检查点控制请求长度与恢复成本。只有七章均完成后才发布正式正文；正文文件不附内部来源字段和配图指令，这些内容另存依据文档。结构校验只排除已知错误，不能替代对项目主张和行文质量的阅读。
