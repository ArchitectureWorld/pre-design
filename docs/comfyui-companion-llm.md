# ComfyUI 生图工具与配套 LLM

前期策划的全局子 Agent 配置支持 `Comfyui-PIC / Klein` 与显式选择的 LLM 配对。所有项目共用，主选项及每个备用选项分别保存配对；修改只用于新任务，已启动的任务和备用链使用启动时快照。

- 在 DSH 启用现有 ComfyUI 插件和 `comfyui_pic` 工具，局域网地址、工作流及模型文件仍在该插件的 DSH 设置中管理。
- 在生成图像类中选择 Klein 后，必须同时选择支持工具调用的 LLM；候选来自同一 DSH 模型目录。插件不会借用其他功能类或父会话的模型。
- 前后端均校验配套选择。ComfyUI 不可作为自己的配套 LLM，也不可用于文本、检索或审图类。普通生图 API 保持直接输出图像的方式。
- 子会话实际请求配套 LLM，工具权限只开放 `comfyui_pic`，禁止继续委派和重复提交同一图片。模型可见工具和运行时权限采用同一策略。
- 图片必须来自当前原生子会话中与工具调用关联的成功结果，并等待该子会话结束。用户参考图、助手自行输出的图片和失败工具结果不能充当 ComfyUI 产物。
- 执行记录保留 ComfyUI 路由、配套 LLM、配置版本和备用顺序；实际 LLM 从原生请求记录核验。已卸载子会话使用只读持久化记录核验。图片资产的生成方仍为 ComfyUI / Klein。
- 配套模型或工具不可用时按既有备用链处理；结果未知的请求保留恢复身份，避免重复生图。失败项记录并报告，其他独立工作继续。

配置格式示例：

```json
{
  "provider": "Comfyui-PIC",
  "model": "Klein",
  "llm": { "provider": "your-dsh-provider", "model": "your-tool-capable-llm" }
}
```

DSH 目录目前未声明每个模型的工具调用能力，用户须选择具备该能力的 LLM。目录存在和静态测试通过不代表局域网 ComfyUI 在线，真实出图需另行核验。
